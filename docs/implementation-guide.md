## 2. 系统分工与数据路线

```text
发送验证链：
随机比特 → Python 调制/脉冲成形 → 数字 I/Q
        → 发送缓存与 AD9361 → 已知射频信号 → 接收端

接收最终链：
AD9361 接收、变频和采样 → 原厂 FPGA 收数接口
                       → 项目滤波/分帧
                          ├→ 加窗 → FFT → 功率谱 → ARM 参数估计
                          └→ 保留复数 I/Q → ARM 预处理 → AI 推理
                       → 带帧编号的结果 → USB/网口 → 电脑显示

旁路与验证：
保留可保存原始 I/Q 的路径，用于 Python 对照、模型训练和问题复现。
```

| 部分 | 通俗解释 | 本项目职责 |
| --- | --- | --- |
| AD9361 | 把真实高频信号变成适合计算的一串数字，也能反向发射 | 射频接收/发射、变频、采样及芯片内部滤波 |
| FPGA / PL | 按时钟不断处理数据的并行流水线 | 接收数据整理、需要的 FIR、加窗、FFT、功率谱、分帧与缓存 |
| ARM / PS | 板上的小电脑 | 设置射频参数、组织数据传输、计算物理参数、运行轻量 AI |
| 电脑 | 开发、训练与观察界面 | Python 参考、模型训练、早期推理验证、最终显示与日志 |

Zynq-7020 的基础结构是 ARM Cortex-A9 加 FPGA，没有原先 FMQL 路线中的专用 NPU。本版将 AI 部署到 ARM CPU，不把 FPGA 神经网络加速器加入六周必做范围。[AMD 平台资料](https://www.amd.com/en/products/adaptive-socs-and-fpgas/soc/zynq-7000.html)

AD9361 已有射频变频、ADC 和数字滤波，因此当前不需要再增加外置 ADC。额外 FPGA DDC 只在以后需要数字搬频/多通道选择时再讨论。[AD9361 官方说明](https://www.analog.com/en/products/ad9361.html)

重要区别：
- IIO 软件能显示 FFT，证明的是工具可以分析采样，不证明你们的 FPGA FFT 已经完成。
- 芯片内部 FIR、厂商接口和团队新增的 PL 模块要分别写明来源。
- AI 必须保留幅度和相位信息；不要默认只给它一张功率谱。
- 相对功率在 AI 幅度归一化前测量。归一化用于让模型关注形态，会改变幅度参考。
- 本版以数字 I/Q 波形作为“时域显示”；它不是直接画出 GHz 载波每次振荡。
- 同一块板 TX/RX 可在原厂支持的配置下做受控环回，但共享时钟条件较理想。若没有独立发射设备测试，应在报告中注明。

## 3. 固定学习与实现顺序

每个新功能都执行：

原理讲解 → Python 黄金参考模型 → 理论预期结果 → 单元测试 → FPGA/ARM 等目标实现 → 与参考结果对比 → 上板 → 性能测试 → 文档记录。

- 黄金参考：先在 Python 中算清楚“正确答案应当是什么”，供后续硬件核对。
- 理论预期不能只复制程序输出。例如测试单音的频率位置、滤波器对高低频的不同影响。
- FPGA 先有浮点参考，再补与硬件位宽、舍入、饱和/溢出规则相同的定点参考。
- 仿真比对通过后才上板；上板后再与同一数据的参考结果核对一次。
- AI 对应流程为：解释任务 → 数据与预处理参考 → 可核验的数据预期与基线 → 测试 → 训练/部署实现 → 浮点与部署结果对照 → 板端推理 → 速度/准确率测量 → 模型记录。
- 原厂启动和库兼容性检查属于基础条件验证，不强行为它们补一个没有意义的算法黄金模型；不适用项写清理由。
- 不一次生成整套工程。后续每轮只做下面一个小任务，遇到新概念先教学。

## 6. P01：用 IIO 确认真实接收通道

先学：串口负责登录与查看日志；IIO 是软件访问板上采样设备的一种接口；USB/网口负责传送数据。

步骤：
1. 用已经成功的版本打开 IIO Oscilloscope，建立板卡的 IIO 连接。
2. 确认射频控制接口与接收采样设备已出现。现有工程常见名称分别为 ad9361-phy、cf-ad9361-lpc；以实际固件为准。
3. 在 Capture 中选择一条接收通道的 I 与 Q。两条数字序列共同表示一路信号，不是两个独立射频信号。
4. 先看时域变化，再看频谱；记录采样率、调谐频率、射频带宽、接收增益。
5. 保存一段数据或采样证据，确认采样会持续更新。

验收：通道存在，能收到非固定常数且格式合理的数据，采集可重复开始/停止。此时只确认采集链路；看到噪声不等于已经接收到目标通信信号。
若通道仍为空：读取本次设备列表与启动日志，先解决设备连接或驱动初始化问题；不得用旧日志替代现状，也不要靠反复点击播放或写寄存器解决。
产物：首次真实接收记录、IIO 配置、截图/样本；EXP-P01。
工具用途参见 [ADI IIO Oscilloscope 文档](https://analogdevicesinc.github.io/system-level/software/iio-oscilloscope/)。

## 7. P02：让 Python 可重复读取和保存 I/Q

先学：
- 采样率：一秒取得多少个样本；这里一个复数样本包含一对 I 和 Q。
- I/Q：描述信号变化的两个互相配合的数，可写成 x[n] = I[n] + jQ[n]。
- 一帧：从连续样本中取出的一小段，便于分析。

步骤：
1. 核对现有 Python 环境与板卡 IIO 接口兼容性，选定 libiio/pyadi-iio 适配方式。
2. 写最小接收程序：连接 → 读取固定长度 I/Q → 打印长度/类型 → 保存 → 退出。
3. 读取并保存采样率、调谐频率、RF 滤波带宽、增益模式与值、时间、设备与固件版本。
4. 确认 I/Q 顺序、符号、有效位、存储位宽和数值比例。AD9361 的 ADC 有效位不等于文件的容器位数。
5. 增加重复采集、清楚的错误信息、样本计数和配置回读。
6. 对同一份保存数据在 Python 与 IIO 中比较；频谱比较必须对齐 FFT 点数、窗函数和缩放，不能直接比较两次随机噪声的曲线。

验收：可以不依赖手动点击图形界面取得真实数据；文件能被重新载入且配置完整。
产物：最小接收程序、离线回放、数据格式说明、EXP-P02。
优先使用现有工程 Python 环境，不为每个脚本另建一套依赖。
参考：[ADI Python 接口](https://analogdevicesinc.github.io/pyadi-iio/)。

数据文件建议：开发时保存 .npy/.npz 与 JSON 元数据；持续高速记录可用明确定义的二进制格式。图片不能替代原始 I/Q。

## 8. P03：建立一个已知单音的收发验证

先学：单音像只有一个音高的声音，适合检查频率位置；发射端把数字 I/Q 转成射频，接收端再转回来。

步骤：
1. 在 Python 生成已知频率、幅度的复数单音并绘图、测试。
2. 根据原厂支持方式送入 TX，确定发射调谐频率与基带偏移，先选择可辨认且避开零频直流峰的位置。
3. 核对实际板卡 TX 输出、RX 允许输入、线缆损耗和衰减器后确定环回连接。未经核算不得把 TX 直接接 RX；本计划不凭空指定某个固定衰减值。
4. 读取真实接收 I/Q，检查频谱峰是否落在理论位置。
5. 改变基带频率，观察峰随之移动；固定接收增益并改变已知衰减，检查接收相对功率变化。
6. 保存发送文件、接收文件与所有配置。发送和接收数值幅度不会天然相等。

验收：输入改变能在接收结果中按预期体现；频率方向没有翻转，I/Q 顺序正确，接收未发生明显削顶。
产物：单音黄金模型、测试与受控 RF 收发记录；EXP-P03。

同板环回适合初次验证；独立收发设备有额外频偏和时钟误差，后续泛化测试需要另作记录。若采用无线演示，之后再根据实验场所与频段确定具体配置，本轮不安排发射操作。

## 9. P04：依次生成 BPSK、QPSK、16QAM 并采集

先学：
- 调制：用波形的变化表达数字信息。
- 符号：一次选择的波形状态。
- BPSK：两个相差半圈的相位状态，一个符号表达 1 比特。
- QPSK：四个相位状态，一个符号表达 2 比特。
- 16QAM：16 个幅度/相位组合，一个符号表达 4 比特。
- 符号率：一秒发送多少个符号；它不同于采样率。
- 脉冲成形：让符号过渡受控，限制发射波形占据的频带。

按 BPSK → QPSK → 16QAM 的顺序，每类单独完成：
1. 比特到符号映射，手算短序列并单元测试。
2. 确定每符号采样点数，将符号变成可发送的 I/Q 序列。
3. 教学并加入根升余弦等约定的脉冲成形；先理解后设计，不凭猜测复制系数。
4. 统一平均功率、符号率和成形参数，画波形/频谱/理想星座，验证映射和功率。
5. 发射、真实采集，保存标签和配置；查看与理想数据的差别。
6. 换随机数据和采集会话重复实验，避免训练集只有一条循环播放的固定序列。

验收：三类都能独立生成并完成受控收发。标签来自真实发送配置；接收端 AI 不能读取这个标签。
产物：三个调制参考、测试向量、三类真实采集样本、EXP-P04a/b/c。

星座图是把 I 当横坐标、Q 当纵坐标画点。全部采样点的散点图常有过渡轨迹；未经定时/载波同步，不应要求收到的图总是整齐的 2/4/16 个点。同步不是本版完整解调任务。

## 10. P05：建立三项任务的 Python 分析参考

P05 可以先用 P03/P04 的仿真数据开发，随后必须用真实保存数据验证。

### P05a：时域、频谱与瀑布图

先学：
- 时域：信号随时间怎样变化。
- 频谱：能量分布在哪些频率。
- FFT：从一段样本计算频率成分的高效方法。
- 瀑布图：把连续时刻的频谱排起来，用颜色表示强弱。
- 窗函数：减轻截取有限长度数据造成的频谱扩散，需要记录它对幅度和功率缩放的影响。

步骤：时间轴 → 加窗与 FFT → 明确功率谱归一化 → 基带/射频频率轴 → 瀑布图缓存 → 与已知单音及三类调制比较。

关键关系：
- N 点 FFT、采样率 fs 的频点间距是 Δf = fs/N。
- 加窗后实际分辨相邻信号的能力还受主瓣宽度和观察时长影响，不能把 Δf 当作全部分辨能力。
- 射频频率 = 接收调谐频率 + 基带频率，符号方向先用单音验证。

验收：单音位置正确，改变采样率/FFT 点数后坐标仍正确，连续频谱能形成瀑布图。

### P05b：中心频率、占用带宽、相对功率

| 输出 | 本版采用的含义 | 怎么核验 |
| --- | --- | --- |
| 中心频率 | 在选定单信号频带内，取占用带宽上下边界中点，再加接收调谐频率 | 已知发送频率及偏移；说明它是谱中心估计，不保证等于非对称信号的载波频率 |
| 99% 占用带宽 | 在明确的分析范围与噪声处理规则下，累积谱功率从 0.5% 到 99.5% 所跨的频宽 | 独立构造已知边界的功率谱测试；再与固定成形参数的高精度参考及真实采集比较 |
| 相对功率 | AI 归一化前的平均 I²+Q²，或除以固定参考后表示为 dB | 将样本幅度乘 a，功率应乘 a²；固定增益增加已知衰减时相对功率应相应降低 |

步骤：
1. 明确分析频带、目标信号条件、噪声底处理与无有效信号时的状态。
2. 逐个函数实现并编写独立理论测试，规定单位和合理误差容限。
3. 在浮点、已量化、真实数据上运行，记录各自误差来源。
4. 将参数计算与图形绘制分开，方便之后迁移 ARM 和自动测试。

不要把接收机设定的调谐频率直接作为测量答案；不要把 RF 滤波器带宽当作信号占用带宽。
不同增益下的数字功率不可直接比较；若使用 AGC，应记录增益变化并限制比较条件。
若采用 dBFS，必须先定义满量程及复数功率参考；未经过功率校准，不称为准确绝对 dBm。
FFT 窗函数会影响尺度，功率谱积分与时域功率比较应按同一归一化规则处理。

验收：三项估计有明确定义，独立测试通过，真实条件变化趋势正确。
产物：参考分析库、单元测试、三种图、参数误差记录、EXP-P05a/b。

### P05c：需要的 FIR 参考

FIR 可以理解为：对最近若干个采样点分别乘一个系数，再把结果相加，用来保留某些频率、减弱其他频率。

先根据目标信号带宽确定通带/阻带、允许衰减和抽头数，再比较滤波前后；不能为“用了 FIR”随意滤掉调制信息。用于 PL 的滤波器要在 P07 单独验证，芯片内已有 FIR 列为复用模块。

2026-10-09 的浮点候选参考已通过，见 [P05c 记录](experiments/exp-p05c-fir.md)和[讲解](lesson-p05c-fir.md)。其 1 MS/s、居中 P04 波形条件不能替代真实目标频段与采样率设计，定点/RTL/ARM 和真实链路仍待对应验收。

## 11. P06：提前验证 FPGA 和 ARM 的实现条件

本阶段第一周就开始检查，不能等到模型训练和算法全部完成。

FPGA 路线：
1. 找到与当前可用固件配套的 HDL、约束、器件型号、构建说明和 Vivado 版本。
2. 确认新增 FFT/FIR 所选 IP 可仿真、可综合且可用于最终演示，不能最后才发现授权问题。
3. 先原样构建厂商工程，记录输出，理解 AD9361 接口、数据时钟、DMA 和处理器连接。
4. 用可恢复的方式验证未修改工程仍能正常接收，建立可回退版本。
5. 列出项目模块的接入点、时钟域、数据格式和 PS 软件需要的配套变化。

ARM 路线：
1. 读取真实系统、CPU 架构、库版本、可用内存和文件持久化方式。
2. 用交叉编译等适配方法运行一个最小 C/C++ 程序。
3. 用极小模型验证推理运行时、所需算子及输入输出。
4. 实测初步耗时和内存，再冻结模型结构；不假定桌面 Python/PyTorch 可原样搬到板上。

先学名词：
- AXI-Stream：模块间按约定传送连续数据。
- DMA：批量搬数据到内存，减轻 CPU 逐点搬运的工作。
- 交叉编译：在电脑生成适合板上 ARM 执行的程序。
- 位流/bitstream：配置 FPGA 电路的文件。

验收：原厂工程能再构建并保留采样能力；板上能运行小型推理实例。
产物：构建环境清单、构建日志、恢复基线、ARM 兼容性记录；EXP-P06。

## 12. P07：把高速处理真正放到 FPGA

先学：定点数、流水线、数据有效/准备信号、帧边界、缓存、时钟约束。只讲当前模块需要的知识。

建议先固定一种配置，例如 1024 点 FFT，使用实测稳定且兼容的采样率。点数为起始设计选择，采样率、位宽和 FIR 参数需要 P03/P05/P06 的依据。

顺序：
1. 定义输入输出契约：I/Q 顺序、位宽、小数位、帧长、FFT 顺序、缩放、舍入和溢出处理。
2. 根据浮点参考写定点参考，生成测试向量。
3. 分别完成数据整理、必要 FIR、分帧、加窗、FFT IP 封装、功率谱和输出模块。
4. 每个新增模块都有自检 TestBench；使用 IP 也要测试配置、封装及连接。
5. 测试零输入、单音、双音、随机 I/Q、三类调制、近满量程输入、复位、数据暂停与下游阻塞。
6. 同一输入与定点参考比较；可逐位一致的模块按位比较，否则预先说明误差来源与容限。
7. 集成到可构建的原厂工程，检查时钟域交互、数据量及新 DMA/寄存器的配套软件。
8. 完成综合与实现，记录资源和时序，再按可回退方案上板。
9. 先用可控测试数据或离线回放比对，然后处理真实接收数据。
10. 记录滤波群延迟、FFT 帧延迟、吞吐、缩放与总误差。

连续 ADC 不一定能随意暂停。如果后级处理来不及，必须有明确缓存/抽取/选帧与丢失计数方案；不能因为 AXI 有握手，就假定射频样本可以无限等待。

验收：板上输出与相同输入的参考结果一致到预定容限；时序满足目标约束，数据没有无记录丢失，报告能指明实际工作的 PL 模块。
产物：RTL、IP 配置、TestBench、测试向量、仿真报告、时序/资源报告、硬件实验记录。

如果 FIR 未进入最终 PL，则在范围与报告中明确说明；核心 FPGA 频谱链仍必须真实实现，不能以电脑 FFT 替代却宣称完成。六周内优先使用合适 IP 完成算法集成，不要求从零手写 FFT 蝶形运算。

## 13. P08：建立可信的 AI 数据集

先学：标签是已知答案；训练集用于学习，验证集用于选择方案，测试集只用于最后评价；SNR 是信号相对噪声的强弱。

步骤：
1. 规定三类数量、每帧长度、I/Q 排列、采样率/符号率范围及预处理。
2. 用仿真数据学会控制调制、噪声、频偏、相位等因素；用真实数据确认硬件差异。
3. 真实采集分多次进行，每类覆盖相同的主要频率、功率、增益和符号率条件，避免模型通过“某类总更强”猜标签。
4. 每条原始记录保存发送随机序列/种子、采集会话、配置、时间和设备信息。
5. 先按独立原始波形或采集会话划分，再切帧；不能把同一长记录的相邻片段随机分到训练和测试。
6. 推荐起始划分 70%/15%/15%，实际比例依据独立会话数量调整；保证每类都有独立测试会话。
7. 仿真可先采用较容易的 SNR 条件，例如 10/15/20 dB，再根据需要扩展。这是设计范围，不是已采集事实。
8. 真实 SNR 要说明噪声测量/估计方法；发射增益或距离不能直接充当 SNR 标签。无法可靠标定时写“未标定”，不能编造数值。
9. 固定并保存划分清单，量化校准使用训练数据中的代表性子集。

验收：数据可追溯，集合无会话/重复波形泄漏，三类条件平衡，另有封存的真实测试数据。
产物：数据说明、采集配置、划分清单、统计表与处理脚本。

合成加噪接收数据和实际低 SNR 无线接收必须分开记录。空口频偏、干扰、多径不等同于只加白噪声。

## 14. P09：训练轻量 AI，先在电脑验证

先学：
- 训练：用带答案的数据调整模型。
- 推理：用已训练的模型判断新数据。
- 一维 CNN：沿 I/Q 时间序列寻找短时变化规律的小网络。
- 过拟合：熟悉练习数据，但遇到新的采集条件表现变差。
- 混淆矩阵：看每一类被误判成哪一类。

步骤：
1. 根据 P06 已证实可部署的算子，建立小型一维 CNN；输入为固定长度的 I/Q，不预先采用大网络。
2. 规定直流处理、幅度归一化等预处理，保证训练和接收程序完全一致。
3. 运行训练，保存随机种子、结构、超参数与验证集结果。
4. 用验证集选择模型并查看典型错误，测试集不参与反复挑模型。
5. 固定模型后在独立真实测试集输出整体/逐类准确率、混淆矩阵、可用 SNR 分组表现。
6. 做一项简单传统特征分类基线作为比较，评估 AI 改进和代价。
7. 测电脑推理时间、参数量、模型大小；检查模型是否学习了无关采集条件。

验收：在独立真实数据上达到预先约定的目标并可复现。建议初始目标为约定较高 SNR 条件下三类总体准确率 ≥90%，同时报告最差类别及样本量；这是待验证目标，不能当成已达成结果。
产物：模型文件、训练配置、数据版本、模型卡、评估报告。

模型最高输出得分可以展示，但未经校准不能解释成“有同样百分比的概率正确”。无有效信号时可暂停分类；这不等于已经实现任意未知调制的拒识。

## 15. P10：ARM 推理与量化对照

先学：量化是用较少位数近似存储/计算权重与激活，可能节省内存和计算，也可能损失识别率。

步骤：
1. 使用 P06 验证过的运行环境导出/部署模型。
2. 先把同一批保存的 I/Q 分别送入电脑参考与 ARM，核对预处理、逐类输出与最终类别。
3. 测模型大小、峰值内存、单帧推理时间，并与目标分类更新频率比较。
4. 用训练集代表样本做量化校准，尝试兼容的 INT8 方案。
5. 在同一个封存测试集上比较浮点与量化的总体/逐类准确率、混淆矩阵、板端耗时和内存。
6. 若量化不支持、没有加速或精度明显退化，记录原因与实测结果，可保留满足时间目标的浮点版。
7. 接入真实采集帧；配置推理队列上限及取帧规则，避免越运行结果越滞后。

验收：模型真实运行在板上 ARM，结果可与电脑版本复核，速度支持约定更新率。电脑实时推理可以作为中间演示，但不能称为板载 AI 已部署。
产物：部署程序、浮点/量化对比表、ARM 性能记录、EXP-P10。

不要在看到模型运行较慢后直接扩展到自研 FPGA 神经网络加速器；先缩小模型、选择支持算子并合理设置分类频率，范围变更以后再讨论。

## 16. P11：统一实时界面与系统集成

先学：采样、FFT 更新、AI 分类和屏幕刷新是不同速度；高采样率不等于每个样本都要画到屏幕。

界面最低内容：
- 连接/采集状态、配置中的调谐频率、采样率、RF 带宽、增益。
- I/Q 时域波形、频谱、瀑布图。
- 估计中心频率、99% 占用带宽、相对功率。
- AI 类别、模型得分、模型版本。
- 数据/结果时间、运行状态、更新率、已知丢帧或覆盖信息。
- 开始/停止、配置、保存样本和记录结果。

步骤：
1. 固定 ARM 到电脑的报文：格式版本、帧编号/样本索引、配置编号、数据类型、缩放、结果时间。
2. 频谱和 AI 使用不同帧长或更新频率时，标明各自时间，不能把旧分类贴在新频谱上。
3. PC 显示收到的 FPGA/ARM 结果，保留离线回放方式便于排错。
4. 接收、计算、传输和绘图分开调度，缓存有上限并记录丢弃。
5. 保存原始样本与结果能追溯到相同配置。
6. 改变采样率、频率或增益后，清理旧缓存并更新标记，避免混用两种配置。
7. 演示时接收分析端不读取发送模式标签；发送记录只用于验收对照。

数据量示例：若每对 I/Q 各按 16 位存储，2 MS/s 单通道原始负载约 8 MB/s，尚不含传输开销。这个例子不是板卡已达成性能，也不是要求本项目必须采用 2 MS/s。可将平均频谱、有限时域帧与结果传回电脑，原始数据按需保存。

验收：真实输入改变后，图形、参数和识别结果按时间更新，无长期积压，断开连接时明确显示失联而非维持“正常”。
产物：统一界面、数据协议、运行说明、系统联调记录。

## 17. P12：性能验收、稳定性与比赛材料

验收前先冻结测试条件与目标，以下为起始建议，后续调整必须说明原因而非掩盖失败。

| 项目 | 建议验收方式或起始目标 |
| --- | --- |
| 三类识别 | 在约定较高 SNR、独立真实测试集上总体准确率以 ≥90% 为起始目标，报告逐类表现 |
| 中心频率 | 用已知输入验证；初始可按约 1–2 个 FFT 频点间距建立误差目标，注明窗、噪声与频率基准误差 |
| 占用带宽 | 先用独立谱数据核验算法，再报告真实与参考的绝对/相对误差及噪声条件 |
| 相对功率 | 固定增益、无削顶，改变已知衰减；记录理论变化与实际变化 |
| 界面 | 起始争取 ≥5 次/秒可视化更新；可降低显示点数，不伪造数据 |
| AI | 起始争取 ≥2 次/秒分类；实测平均及较慢情况下的推理时间 |
| 端到端响应 | 单独测从输入变化到结果更新的时间，起始争取 ≤1 秒；模型切换/投票/缓冲均计入 |
| 数据完整性 | 记录采样、分析帧数、选帧规则、已知丢失和无法观测的部分 |
| FPGA | LUT、FF、BRAM、DSP，约束时钟、最差时序裕量、模块延迟和吞吐率 |
| ARM | CPU/内存使用、模型耗时、并行采集下的负载 |
| 稳定性 | 按固定配置连续运行至少 30 分钟；做重复启动与重新连接测试 |

“实时”必须同时说明观察带宽、采样率、分析帧覆盖、刷新率和延迟。只处理间隔帧的系统可以持续更新，但不能声称对所有采样点做了无间断识别。

执行步骤：
1. 用三类独立测试信号依次验证；切换顺序变化并记录。
2. 在已经定义的频偏、功率、SNR 和符号率范围内测试，报告失败条件。
3. 分别评估 FPGA 算法、ARM 推理与含传输的系统时间。
4. 连续运行并保存日志，检查温升导致的状态变化、内存增长、丢帧和结果滞后。
5. 按全新启动复现一遍，确认关键配置与程序保存在可持久化位置。
6. 整理系统框图、团队贡献、模块测试、模型卡、性能表、演示脚本与视频。
7. 固定最终代码/模型/固件版本与校验值，保留一套已验证可恢复的演示配置。

演示脚本建议：启动并连接 → 单音确认频率测量 → 切换三种调制 → 展示图形/参数/分类随输入变化 → 改变一个已知参数 → 展示实测报告。
阶段尚未完成时如实说明，不用目标数字填充结果表。

## 20. 如何让 AI 按此路线帮助你们

每轮把目标限定到一个编号和一个可验收小结果，附上上一轮结果。以下文字可直接复用：

> 我们做“基于 Zynq 的通信信号实时分析与 AI 调制识别系统”，平台是璞致 P201/P203、Zynq-7020 + AD9361。请读取 implementation-guide.md 和上一条实验记录。这次只推进【任务编号与小目标】。
> 我们会 Python、C/C++、基础 Verilog，通信与 DSP 是初学者。请先用直观语言解释本步新概念，再按“原理 → Python 参考 → 理论预期 → 单元测试 → 目标实现 → 参考对比 → 上板 → 性能 → 记录”推进；不适用项说明理由。
> 给出准确的操作位置或文件、少量可执行步骤、成功表现和失败时该保存的证据。不要一次生成后续全部项目，不增加未经讨论的功能。涉及接线/量程/固件时依据实际板型手册。FPGA 必须有 TestBench，模型必须有数据划分/准确率/量化记录，优化必须有资源/时序/延迟/吞吐记录。
> 当前完成情况：【填入】。本次输出、截图或文件：【填入】。请先判断现有证据再继续，不把目标当实测结果。

按任务向 AI 提供材料：
- P01：当前 IIO 连接/通道截图；若失败，当前设备名与启动日志。
- P02–P05：小段 I/Q、完整采集配置、参考结果和测试报错。
- P06–P07：原厂工程版本、工具版本、模块接口、TestBench、仿真/实现日志。
- P08–P10：数据清单、划分规则、模型配置、训练/部署日志和评估表。
