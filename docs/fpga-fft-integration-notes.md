## 为什么不能把 FFT 直接串进去

现有 Python/IIO 使用有符号 12 位有效数据、16 位存储和指定 I/Q 通道。FFT 输出是每分量 27 位有效数据、64 位复数打包，还带频点索引和 TLAST。如果替换原 DMA 的原始 I/Q，旧驱动及软件就会把频谱结果误解为时域采样，破坏已通过的采集链路。

ADC 也不能因为 FFT 或下游暂停就停止实际采样。即使流水线 FFT 单独吞吐足够，仍需要缓冲、溢出检测、帧边界、控制配置与跨时钟设计；接口能握手不等于真实 ADC 可以被反压。

## 建议的接入顺序

1. **保留原始 RX→cpack→DMA→IIO 路径**，先从选定 I/Q 的 valid/data 分出分析支路。确认 I/Q 同周期有效、位宽、符号与当前抽取／旁路状态。
2. 支路加入有限缓存和明确的溢出／丢块计数。需要切到 100 MHz 时，用经验证的异步 FIFO；不能直接把 RX 时钟当成 100 MHz，也不能把多位总线逐位同步后当作一致数据。
3. 1024 个实际接收样本组成一帧；只在实际接受样本时递增计数，第 1024 点打 TLAST。复位／溢出丢弃不完整帧并记录，不把下一帧拼到半帧后面。
4. Hann 窗定点乘法、FFT、功率平方与 PSD 归一化分别明确位宽、舍入及溢出边界。与现有 Python 同窗、同 Fs、同频点顺序对比。
5. FFT／PSD 结果走独立结果缓冲和适当的软件接口。先定义结果头中的版本、帧号、实际 Fs、FFT 长度、数据格式、计数和状态，再设计 DMA／驱动／读取程序，不能沿用原始 12/16 位 IIO 数据标签。
6. 先离线 TestBench，再完整工程布局布线、CDC 和接口约束，之后才安排有恢复方案的上板；最后与同一输入的 Python 结果和性能指标核对。

## 候选选择

burst 约 13.94 MS/s 的独立仿真吞吐不覆盖 30.72 MS/s 原始流，适合明确降低采样率后的支路；流水线候选的功能、资源和吞吐见 [当天记录](experiments/exp-auto-20261015.md)。两者都不自动解决原 FIR 约 1.515 MS/s 的结构限制，也不自动把采样率变成 CNN 训练使用的 1 MS/s。

原厂 8 倍抽取功能值得复用评估，但启用后有效采样率、驱动报告、带宽与混叠都要实测；30.72/8=3.84 MS/s，仍不是 1 MS/s。不能为了让数字看起来匹配而修改文件中的 Fs 标签。
