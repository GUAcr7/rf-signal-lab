## 现在停止时保存什么

- AI 写入的代码、说明、实验记录已在电脑硬盘。真实 iq.npy/metadata.json、模拟 NPZ、图、报告和用户截图证据也已保存。
- 若用户另有尚未保存的代码编辑，先手动保存；若另有新采集但只在窗口/内存里，先导出并确认文件存在。已有模拟回放不需要另存运行位置才能保留源数据。
- 保留整个 rf-signal-lab 工程，尤其 results 文件夹。results 被 Git 忽略，提交代码或仅复制源码不会包含这些样本/截图/报告；备份或迁移时需一并复制。
- 保留原 SD 卡及已经验证可启动的启动文件，不格式化、不重新烧录。电脑工程与 SD 启动系统是不同的保存位置。
- 停止采集并关闭相关窗口，再处理板卡关机/断电。板端若正在写文件或烧写固件，不在写入过程中拔电。
- 若使用原厂 Linux 的正常关机命令，应先确认当前系统支持该命令并观察停机提示；本次没有重新核验 poweroff/halt 的支持情况，也没有代替用户执行关机。

断电后：板端运行程序、接收缓存和临时设置不能假定保留；已落盘的电脑工程/样本与 SD 启动文件不因正常断电而需要重新生成。

### 需要板卡实时采集

1. 保持原 SD 卡/启动设置，用已经验证的供电与数据线重新接回，等待启动。
2. 检查实际 USB 网卡及串口枚举。最近记录是电脑 192.168.2.10、板卡 192.168.2.1，串口 COM5；这是历史值，下次不机械照搬。
3. 核验网络后，重新建立 IIO/Python 连接并确认模型是实际 P201，控制与 RX 通道可见。单独 ping 成功不作为采集成功。
4. 读回本次采样率、RX LO、RF 带宽和增益模式；按将做的实验恢复并记录配置，不假定掉电前的临时值仍在。
5. 先取一个短样本验证，再继续当天任务。如果缺设备/通道，保存当前启动/连接日志，先诊断，不从头盲目安装或烧录。

最近采集配置供对照：Fs=30.72 MS/s、RX LO=2.4 GHz、RF BW=18 MHz、slow_attack 自动增益。它们不是所有后续任务固定使用的参数，更不是当前硬件状态的新读回。
