# 三人协作：一块板，两条离线开发线

更新：2026-09-30。目标、功能范围和 P00–P12 编号沿用 [实施指南](implementation-guide.md)。本文调整人员安排，不新增功能，也不将尚未完成的硬件验收改成通过。

按现有实验记录，P01/P02 已完成；P03 的 Python 参考和板内 RX 数字单音、变频、变幅通过，真实 RF 收发仍待验证。这是已有记录的状态，不代表今天重新核验过板卡连接。

## 1. 各自负责什么

| 人员 | 主责 | 对应原路线 | 交给队友的成果 |
| --- | --- | --- | --- |
| A：持有板卡的同学 | 原厂平台、真实收发、数据采集、板上验证、ARM 部署与最终系统联调 | 继续 P03、P04 的真实收发；P06 板端核验；P07/P10 上板；P11/P12 集成 | 带配置与来源的 I/Q、板端日志、接口与资源信息、实测结果 |
| B：信号分析与 FPGA | Python DSP 黄金参考、绘图与参数计算、定点参考、RTL/IP 仿真与构建 | P05；P06 的 HDL/Vivado 检查；P07 | 分析函数、测试向量、TestBench、构建脚本、资源/时序报告及接入说明 |
| C：通信信号与 AI | 三类调制的离线生成、仿真信道、数据集、轻量模型、导出与部署准备 | P04 的软件生成；P08/P09；P06/P10 的模型兼容性准备 | 可重现发送波形、数据清单、预处理与推理程序、模型与评估报告 |

A 负责最终界面与系统数据流的整合，B 提供可复用的图形/参数计算组件，C 提供预处理和识别接口。先能用保存数据把三部分接起来，再把数据来源切换成板卡。各自有主责，不要求 A 独自完成 B/C 的调试；上板时模块作者一起看同一份输入、输出和日志。

## 2. 所有人先掌握的共同知识

只围绕第一个小实验理解以下内容，不必先学完通信原理或 DSP 课程：

- I/Q：同一个时刻的一对数，用复数 `x[n]=I[n]+jQ[n]` 一起表示信号。文件里实部是 I，虚部是 Q。
- 采样率：每秒得到多少对 I/Q；符号率是每秒表达多少个调制状态，两者不同。
- 一帧：从连续样本中取出的一小段，便于分析或交给模型。
- 时域/频域：前者看数值随时间如何变，后者看信号能量主要集中在哪些频率。
- 仿真、板内测试、真实射频：数据来源不同；哪一种通过，就只记录哪一种通过。

共同起步产物：每人在自己的电脑读入同一份 P02 `iq.npy` 和 `metadata.json`，打印样本数、类型、采样率，画出 I、Q 随时间变化的曲线。能复核文件校验值和数据一致性，无需连接板卡。

## 3. B：无板完成 DSP 与 FPGA 的学习准备

按以下顺序，每次只做一个小实验：

1. **离线回放与 FFT。** 复用已有单音参考。FFT 可理解为查出这段波形包含哪些频率。先确认 30.72 Msps、1024 点下频点间隔 30 kHz，0.96 MHz 的峰位正确；再改变频率、采样率和点数，核对坐标。
2. **频谱与参数参考。** 学窗函数、功率和带宽的含义，再实现频谱、瀑布图缓存、相对功率、中心频率和 99% 占用带宽。用答案已知的合成输入做测试；算法与绘图分开。真实 RF 频率方向尚未验证时，相关显示注明条件。
3. **FIR 与定点。** FIR 是最近若干样本分别乘系数后相加；定点是用有限位数表示数值。先做 Python 浮点参考，确定信号带宽和滤波需求，再做定点舍入/溢出参考；不为了增加模块而随意滤波。
4. **FPGA 仿真。** TestBench 是在电脑里给电路喂数据、自动比较结果的程序。使用同一组 Python 测试向量，先验证数据整理/分帧，再接 FFT IP 和必要 FIR，逐模块与定点参考比较。加入复位、数据暂停和下游接收不及时的场景。
5. **原厂工程重建。** 这项与上述学习同步提前检查：找到匹配当前固件的完整 HDL、约束、芯片具体型号、构建说明和 Vivado 版本；确认所选 IP 可仿真、综合及用于最终演示。先原样重建，再讨论插入自有模块。没有板也可以做仿真、综合和实现，但板上时钟/数据/接口仍交由 A 实测。

第一周优先交付：离线回放、正确的单音 FFT 图及自动测试、原厂 HDL/工具版本清单。随后每完成一个模块交付参考输入输出、TestBench、仿真报告；有综合实现结果时再附资源和时序报告。

无需从零手写整个 FFT。不要以原厂 BOOT.bin 已能启动，推断已拥有能修改和重建的完整 FPGA 工程。

## 4. C：无板完成通信信号与 AI 的学习准备

按以下顺序推进，调制生成代码由 C 主责，A 复用这些波形进行后续发送，避免两套实现不一致：

1. **从 BPSK 开始。** 理解比特到两个相位状态的映射，复用已有 BPSK 映射测试；再学习每符号多个采样点和脉冲成形（让相邻符号平滑过渡、控制频谱宽度）。先画出波形、频谱和星座点，再扩展 QPSK、16QAM。
2. **建立有记录的仿真数据。** 标签是已知的调制类别。记录随机种子、样本数、调制方式、采样率、符号率、成形参数及功率尺度。先学习 SNR（信号相对噪声的强弱），再加入有定义的噪声、频偏和相位变化。
3. **学会训练与评估。** 训练集像练习题，验证集用于选择方案，测试集用于最后评价。先按独立生成记录/采集会话划分，再切帧；不能将同一条波形的相邻切片随机分到训练和测试两边。三类的采样率、符号率、功率和噪声条件要平衡，避免模型凭无关条件猜标签。
4. **建立轻量模型。** 先用小型一维 CNN 学习沿 I/Q 序列的变化特征。保存预处理、结构、随机种子、参数量、训练配置、逐类准确率、混淆矩阵和电脑推理耗时。仿真准确率只说明仿真数据上的表现，真实数据到齐后另做评估。
5. **提前检查 ARM 部署。** Zynq-7020 使用 ARM Cortex-A9 与 FPGA，本项目先把模型部署到 ARM。C 准备极小模型、导出程序及电脑参考输出，由 A 尽早在实际板端验证库、算子、ABI 和内存是否兼容，再冻结模型结构。量化是在更少位数下近似计算，需记录浮点与量化后的差异；未做量化就如实写“待验证”。

第一周优先交付：BPSK 短序列映射与测试、第一份有完整参数记录的仿真 I/Q、数据划分方案。基础较快完成后，再训练三类小模型；不要求第一周把复杂信道和模型部署全部做完。

电脑先做小规模训练即可；有 GPU 可以使用，不以购买 GPU 作为开工条件。板端推理兼容性尚未核实前，不假定电脑 PyTorch 可直接安装到板卡运行。

## 5. 无板队员需要拿到的已有资料

代码与文档通过同一个 Git 仓库共享；以下原始数据被当前 `.gitignore` 排除，需要单独复制完整目录，不能只给 Git 地址：

- P02 示例：`results/p02-20260928T122013158254Z/`，包含 `iq.npy` 和 `metadata.json`。可用 `experiments/p02_replay_record.py` 离线回放。
- P03 板内单音：`results/p03-rx-bist-20260928T130631955709Z-frame1/`。元数据与 P02 配置字段不同，应按记录来源解析；不要把只读 P02 字段的回放脚本直接当成通用 BIST 回放工具。
- 共同文档：`docs/p02-iq-data-format.md`、`docs/experiments/EXP-P02.md`、`docs/experiments/EXP-P03.md` 和本指南。
- B 另外需要原厂完整 HDL/约束、构建说明及芯片手册；具体工具版本按工程核实。
- C 另外需要调制参考与测试、数据格式、A 提供的板端架构/系统环境记录和后续真实采集计划。

P02 数据没有已知的 BPSK/QPSK/16QAM 标签；P03 BIST 是芯片产生的数字单音。它们能用于回放、绘图和程序接口检查，不能当三类调制训练样本。真实采样率、增益或 SNR 没有记录/标定时写“未知”，不补造。

每位队员在自己电脑建立独立 Python 环境并记录版本，不复制别人的 `.venv`。初始离线回放依赖 NumPy，绘图与测试复用工程的 Matplotlib/pytest 方案；SciPy、PyTorch 按后续任务需要再安装。无板回放不需要先安装 USB 驱动、串口工具或配置 IIO 连接。

## 6. 三个人如何对接

1. **统一输入。** 继续复用 `rfsig.iq_capture.v1` 的 `iq.npy + metadata.json`；新增来源字段、调制标签、会话 ID 等时兼容已有记录。当前 1024 个复数样本可作初始对接帧长，但它不是最终模型输入长度或采样率的承诺。
2. **保留原始数据。** B 的相对功率计算使用 AI 幅度归一化之前的数据；C 的归一化在自己的预处理分支做，不能覆盖共享原始 I/Q。定点 FPGA 输入位宽/缩放另写清楚，不能把 complex128 存储类型误当 ADC 位宽。
3. **统一结果。** B 返回频率轴、谱值/单位及参数；C 返回固定类别顺序、模型分数和模型版本；A 负责把结果接入板端程序与界面。发送端标签只用于评估，不进入接收端模型输入。
4. **交付能复现的结果。** 每次交付包含代码版本、输入文件与校验值、运行方法、理论预期、实际输出和已知限制。一次板上联调只换一个组件，保留能恢复的原厂配置。
5. **固定短时联调。** 每周至少安排两次共同核对：B/C 提交小成果，A 在同一份数据或板卡上验证，结果写入对应 EXP。原厂 HDL 重建和极小 ARM 模型兼容性安排在早期，不等模型训练结束才检查。

建议同一仓库各自分支，公共数据格式由三人确认后修改。测试向量与小报告进 Git；大原始数据和模型权重单独存储并附清单/哈希。仿真通过标“离线通过、上板待验证”；板端结果只能依据 A 提交的实测证据登记。

## 7. 第一周的具体起点

| 时间顺序 | B：DSP/FPGA | C：调制/AI | A：板卡 |
| --- | --- | --- | --- |
| 第 1–2 天目标 | 读相同 I/Q、画 I/Q 曲线、复现已有 FFT 参考 | 读相同 I/Q、复现 BPSK 映射并解释每个数的含义 | 分享已验证样本和记录，继续 P03 真实 RF 条件准备 |
| 第 3–4 天目标 | 对单音峰位/频率轴做测试；查清原厂 HDL 与工具版本 | 做 BPSK 采样波形与成形学习；保存参数和标签 | 核对队友离线输出，整理板端环境供兼容性检查 |
| 第 5–7 天目标 | 交付离线频谱函数和报告；条件具备则试原样构建 | 扩展三类的生成计划和划分清单；数据参考通过后开始小模型 | 安排一次原厂构建/极小 ARM 模型的上板检查，保留恢复点 |

这是分工目标，按各自学习速度调整；没有板的队员不用等 P03 真射频验收才能做这些离线任务。P04 的真实收发、P07 上板、P09 真实测试集评价仍保留各自验收条件。

给 B：

给 C：

> 我负责本项目的调制信号生成、数据集和轻量 AI，目前没有板，通信与 DSP 是初学者。请先读 implementation-guide.md、team-three-person.md 和已有 BPSK 映射代码/测试。今天只解释并复现比特到 BPSK 符号的映射，用短序列给出理论答案和测试；先教学再给 1～3 个步骤。不要直接生成整套模型。后续按采样波形、成形、三类数据、划分、训练、评估推进，仿真与真实数据结果分别记录。
