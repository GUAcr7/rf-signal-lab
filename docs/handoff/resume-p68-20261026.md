# P68恢复：四区接收显示与真实RF/AI联合回归

先读[实验记录](../experiments/exp-p68-rf-dashboard-20261026.md)、`results/p68-active.json`和对应原始报告。P67的“动态尚无人眼确认”已由本轮用户明确观察补齐。其余结论仍看P68独立复核，不用屏幕标签替代分类与数值证据。

## 重要边界

- 旧板外接淘晶驰屏幕交队友；不改其HMI或接口协议。新板使用原P67二进制，原P56模型和P57持久启动保持不变，重上电仍运行P57界面。
- P68只是当前受控三类源的部署回归；冻结源种子已暴露，不产生新的独立AI准确率。P52独立成绩仍为52/54。
- 屏幕上的record 99%宽度是记录统计；电脑的已知单源ROI带宽另列为诊断，尚未成为LCD目标带宽功能。数字功率不是dBm，ADC缺口未知。
- 五分钟会话内仅单音15秒及三类各16秒发送，其余为校准、转场和背景，禁止写成五分钟连续分类。

## 再次上电

1. 从固定入口重新只读认板，检查boot、实际端口、程序、DMA和源状态。不要照抄本次COM或boot。
2. 若P57自动接收仍运行，使用固定入口干净停止；确认空闲才启动任何候选，实板由一个任务独占。
3. 旧板源在RAM，断电后重新`prepare-source`，必要时先`source-off`；新会话重新采背景/单音校准，不跨boot/session复用。
4. 本次用户确认原射频/衰减连接未变；以后换功分器、端口、衰减或不明确时重新核对，不把本条用于批准新接法。
5. 需要复现P68时用项目Python执行`experiments/p68_rf_dashboard_trial.py --link-confirmation results/p68-link-20261026.json`，并在当前接线仍符合该确认、源包已恢复、P67输入哈希不变时执行。它会发射四个有限时窗口，不能作为单纯显示启动命令。

## 优先任务

读本轮测量诊断，完善目标中心频率/占用带宽的有效性判定与数值方法；然后集成LCD与受控持久启动。P67的纯背景四区试验仍可独立复现，无须每次重做RF/AI完整回归。持久启动变化后再安排一次真实断电验收。

P68恢复包是P67/P65基线之上的增量，`results/`必须随ZIP保留。停工状态与是否关机以active对应报告为准，不根据本文历史描述直接操作。
