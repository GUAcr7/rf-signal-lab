## 1. 我们到底在做什么

项目名称：**基于 Zynq 的通信信号实时分析与 AI 调制识别系统**。

最终希望做到：输入一段真实射频信号，系统能显示它的 I/Q 时域波形、频谱和瀑布图，估计频率、占用带宽和相对功率，并在约定条件下识别 BPSK、QPSK、16QAM。分析结果可以传给电脑，之后还要实现脱离电脑的小屏展示。

第一版范围是：**一路接收、一个选定频段、一次分析一个主要目标、三类已知调制**。这些限制帮助我们把算法和工程做扎实。当前三类模型没有接受任意未知通信制式、纯噪声或多信号混合的完整验收。

你参与研发时，始终围绕三个问题推进：

1. 这一阶段的输入是什么，来源是否明确？
2. 我们期望输出什么，有什么独立依据？
3. 实际结果是否满足要求，证据存在哪里？

例如：一张会变化的波形图说明界面拿到了数据；输入已知单音后，谱峰出现在理论位置、改变频率后跟着移动，才进一步证明频率分析正确。

## 2. 一条信号怎样经过整个系统

### 2.1 当前已经验证过的路径

~~~text
实际射频输入／接收机本底噪声（目标来源未知）
  → AD9361：接收、变频、滤波、采样
  → 原厂 FPGA 接口与 DMA：接收数字样本并搬入内存
  → ARM/Linux 与 IIO：让程序读取采样
  → USB 网络／网口 → 电脑 Python
  → 时域、频谱、瀑布图、数字功率与 ROI 统计 → 保存
~~~

这条路径已经取得真实 I/Q，并完成有限块接收、保存、重新开始和独立重算。输入目标未知，所以不能凭这些样本给真实调制分类打标签。

此外，已经在 ARM 上分别验证：读取本地 IIO、处理保存文件的 FIR、软件 FFT，以及对保存合成数据的分类推理。**这些模块分别运行成功，还不等于它们已组成边采边算、持续显示的整条链路。**

### 2.2 项目计划完成的路径

~~~text
已知信号源或经过核验的发送端
  → 同轴线／衰减器等受控路径 → AD9361 接收
  → 原厂 FPGA 收数接口 → 项目分帧／必要滤波
       ├→ 加窗、FPGA FFT、功率谱 → ARM 参数估计
       └→ 保留复数 I/Q → ARM 预处理 → AI 推理
  → 带帧编号、配置和时间信息的结果
       ├→ 电脑统一界面、保存、回放
       └→ 独立小屏（仍需接口、供电和程序联调）
~~~

图中的项目 FPGA 处理、持续队列、真实 RF 的 AI 验证和独立小屏，均属于未完成或部分完成项。ARM 软件 FFT 是已有的可对照实现；它不能替代“FPGA FFT 已完成”的证明。

### 2.3 每个部件负责什么

| 部件／术语 | 通俗解释 | 项目中的职责 |
|---|---|---|
| AD9361 | 射频世界与数字数据之间的转换器 | 接收高频信号、搬频、滤波、转换成数字 I/Q；也具有发射能力 |
| FPGA／PL | 按时钟并行工作的可编程电路 | 原厂收数与接口；计划新增的硬件滤波、分帧、FFT、功率谱处理 |
| ARM／PS | 板卡上的小电脑 | Linux、设备控制、数据组织、参数计算、AI、输出结果 |
| DMA | 批量数据搬运通道 | 将高速样本搬进内存，减少 CPU 逐个搬运 |
| IIO | 程序访问采样设备的接口体系 | 枚举设备、读参数、取得 RX 数据 |
| 电脑 | 开发、训练、观察和复核平台 | Python 黄金参考、训练、早期处理、图形界面与证据管理 |
| 串口 | 字节通信通道 | 当前主要用于登录板端、查看日志；未来屏幕接口需另行核实 |

Zynq-7020 没有专用 NPU。本项目已有的板端 AI 是运行在 ARM CPU 上的 C 程序。

## 3. 先掌握七个概念

### 3.1 射频载波、基带和调制

载波可以理解为承载信息的高频振荡。基带描述要传递的信息怎样随时间变化。调制负责把信息映射为可以发送的波形。

同一套 QPSK 比特和符号，可以放在不同射频频率上发送。因此，载波从 2.4 GHz 调整到另一个支持频率，并不会自动改变调制类别。但实际硬件、线缆、滤波、增益和噪声条件可能改变。

老师说的 70 MHz 附近信号也属于射频。“普通信号”不是严格分类；我们需要判断的是仪器输出与板卡支持条件是否匹配。

### 3.2 I/Q 是什么

一个复数样本写成：

~~~text
x[n] = I[n] + jQ[n]
~~~

I 和 Q 像平面上的横、纵坐标，合起来表示同一接收通道的幅度和相位。样本幅度可由 sqrt(I²＋Q²) 求得，相位可由 atan2(Q, I) 求得。两条曲线不是两根天线分别对应的两路射频。

当前接收图显示的是 AD9361 转换后的数字基带，不是直接描绘 GHz 载波的每一次振荡。

### 3.3 三个最容易混淆的频率参数

以下是 **2026-10-11 最后核验的配置**，下次开机需要重新读回，并非本手册编写时的新测量：

| 参数 | 历史值 | 它回答什么问题 |
|---|---:|---|
| 接收本振 RX LO | 2400 MHz＝2.4 GHz | 把哪一段射频搬到基带附近？ |
| 采样率 Fs | 30.72 MS/s | 每秒得到多少对 I/Q 样本？ |
| 接收滤波带宽 RF BW | 18 MHz | 接收滤波器大致放行多宽的频段？ |

这三者不是一个数。2.4 GHz 的载波，不要求电脑直接以 2.4 GS/s 处理；AD9361 先完成变频。18 MHz 的接收带宽，也不表示目标信号一定占 18 MHz。

### 3.4 一帧与一个接收块

一帧是算法一次取来处理的一段样本。接收块是一次取数得到的数据块，长度可以与分析帧不同。当前电脑监测每块 1024 点；另一次 ARM 实验取过 4096 点的块，再分成 1024 点分析帧。

按 Fs＝30.72 MS/s、N＝1024 计算：

~~~text
块内样本覆盖时长 = N / Fs ≈ 33.33 微秒
FFT 格点间隔     = Fs / N = 30 kHz
~~~

这里的覆盖时长按 N/Fs 计算；第一点到最后一点的坐标差是 (N−1)/Fs。FFT 格点间隔也不直接等于实际测频误差或分辨两个邻近信号的能力。

主机几秒钟里收到几十个块，不代表这几秒的每个 ADC 样本都被保存。块间连续性需要额外证据。

### 3.5 数字格式与物理单位

当前 RX 扫描格式为小端、有符号、12 位有效值存放在 16 位位置中，右移量为 0。原始有效值范围是 −2048～2047。

Python 可能用 complex128 存储这些数据，这只说明容器类型，不说明 ADC 精度变成了 128 位。原始计数也不能直接当作伏特或 dBm。

详细文件说明见 [P02 数据格式](p02-iq-data-format.md)。

### 3.6 dB、dBm 和增益

- dB 表示比例变化。例如功率降低 10 dB，约变为原来的 1/10。
- dBm 表示以 1 mW 为参考的实际功率。0 dBm＝1 mW，−10 dBm＝0.1 mW。
- 接收增益表示接收机内部放大程度；输入变小而自动增益变大时，数字波形幅度可能没有明显下降。

当前使用过 slow_attack 自动增益模式。要验证输入功率变化，需采用适当的固定增益、避免失真并记录设置。绝对输入功率换算还需要标定。

### 3.7 SNR 与模型得分

SNR 是信号功率与噪声功率的比值。我们的合成数据包含名义 10、15、20 dB SNR，但真实采样没有自动因此获得同样的 SNR 标签。

模型输出的 logit 是分类得分；即使将其转换成 softmax 数值，也不能直接把“0.9”解释成经过验证的“90% 正确概率”。真实置信度校准和未知信号拒识尚未完成。

## 4. 你看到的图与按钮在表达什么

### 4.1 左上：I/Q 时域波形

横轴是块内时间，纵轴是数字计数，蓝色 I、橙色 Q。它适合看幅度、突发、异常值和削顶。调制信号或噪声看起来杂乱并不意味着程序错误；仅靠时域外观不能确认调制方式。

### 4.2 左下：频谱与标记

FFT 将时间样本转换为频率成分。当前程序先加周期 Hann 窗，减少有限片段截断引起的谱泄漏，再计算功率谱密度 PSD。

按当前约定，射频频率约为“接收本振＋基带频率偏移”。例如 RX LO＝2400 MHz，基带谱峰为＋1 MHz，则对应约 2401 MHz。物理链路的正负方向仍需已知单音核验。

PSD 的纵轴单位目前基于原始计数平方/Hz。它表示单位频宽内的功率密度，不是直接校准好的输入 dBm。比较不同 FFT 点数或窗的谱峰高度时，需要保留归一化与积分规则。

黄色区域是所选 ROI 内的等尾 99% 谱功率区间，红线是该区间中点。ROI 是“只分析这段频率”的范围。当前历史配置的 ROI 为 −9～＋9 MHz；累计去掉两端各 0.5% 后得到区间。

**ROI 中包含噪声且尚无目标检测，所以这个区间不能直接等同于目标占用带宽，中点也不能直接等同于目标中心频率。**过去显示的约 17.5 MHz 只是一组未知输入的谱统计结果。

### 4.3 右下：瀑布图

每接收一块，就将该块频谱排成一行。横轴是频率，颜色表示谱功率，当前色标下偏黄较强、偏紫较弱。

固定频率的持续单音可能形成竖向亮线；频率跳变时，亮线位置改变；较宽的信号形成亮带。当前纵轴是接收块编号，块间硬件时间缺口未知，不能直接当作连续 ADC 时间。

当前窗口最多显示最近 96 行；会话保存可以包含全部已接收块。屏幕上显示的行数与磁盘保存的块数要分开看。

### 4.4 右上：运行状态与统计

| 字段 | 怎么理解 | 参与研发时检查什么 |
|---|---|---|
| State | 准备、接收、停止、达到上限或出错 | 状态与实际行为是否一致 |
| Received blocks | 已取得块数／本次上限 | 计数增长，停止后是否保持 |
| Fs／FFT | 采样率／频谱长度 | 坐标、单位、配置是否对应 |
| RX LO／RF BW | 接收调谐与滤波配置 | 与已知源和本次记录是否一致 |
| Gain | 增益模式和快照读数 | 自动模式下不能假定增益固定 |
| Mean I²＋Q² | 当前块平均数字功率 | 是否在 AI 幅度归一化前测量 |
| Digital ratio | 相对本会话首个正功率参考的 dB | 新会话参考重建，不能直接跨会话比较 |
| 99% ROI width／midpoint | 未经目标确认的谱区间／中点 | 不把噪声统计作为已知目标参数 |
| Observed blocks/s | 主机取块平均速率 | 不当作 ADC 吞吐或屏幕 FPS |
| Hardware gaps: UNKNOWN | 块间连续性没有证明 | 保留“未知”，不编造丢样数量 |
| RX context released | 接收资源是否释放 | 它是软件连接状态，不是物理线已拔出 |
| AI: NOT CONNECTED | 真实 RX 尚未接分类器 | 不把占位内容当作识别结果 |

## 6. 核心研发步骤：为什么按这个顺序做

### 6.1 用 Python 建立黄金参考

黄金参考就是“先在容易检查的环境里明确正确答案”。例如生成一个频率已知的复数单音，理论上 FFT 峰的位置已知；再比较程序算出的峰。

如果不知道正确答案，FPGA、ARM 和 Python 即使三者输出相同，也可能只是重复了相同错误。所以我们同时保留理论值、独立公式或不同实现的对照。

你可以参与：选一个测试条件，先写出理论预期，再让 AI 说明代码怎样验证，最后查看保存结果是否一致。

### 6.2 保存真实 I/Q 与元数据

原始数据是问题复现的起点。记录至少包括：I/Q、样本数、格式、采样率、本振、RF 带宽、接收通道、增益模式、时间、软件版本和文件校验值。

SHA256 像文件指纹，可以检查文件是否改变，但不能证明采样来源真实或算法正确。仍需配置、设备身份和采集日志。

你可以参与：打开一份记录，将 JSON 中的配置和截图逐项对应；请 AI 重新加载数组，独立计算平均功率和谱峰。

### 6.3 先用已知单音检查完整射频链

单音像一个固定音高，适合确认频率位置、正负方向和电平响应。板内 BIST 已验证数字路径，但它绕过射频输入、模拟接收和 ADC，不能替代外部 RF 试验。

真实单音实验将记录源型号、输出频率／功率、线缆／衰减、接收配置和采样。改变源频率后，接收谱峰应按预期移动；固定接收增益、降低已知输入功率后，数字功率应按预期变化。

你可以参与：核对设备型号、整理预期、操作老师允许的仪器设置、拍摄端口与状态、观察变化并保存。接线和电平依据应先明确。

### 6.4 在信号分析中保持单位和定义一致

时域看样本变化，FFT 看频率分布，PSD 看功率密度，瀑布图看前后变化。中心频率、占用带宽和功率必须说明计算范围、参考和噪声条件。

频谱标定路径要保留原始幅度；AI 可以另外去直流和按 RMS 归一化。若先把每帧都归一化再测输入功率，就可能抹掉原本要测的幅度变化。

你可以参与：对同一份模拟 I/Q 乘 0.5，看频率是否不变、功率是否变为 1/4，即约 −6.02 dB。这是离线算法检查，不算上板衰减实验。

### 6.5 用 FIR 保留有用频段

FIR 可以理解为将一串历史样本按不同权重相加。它能压低某些频率，但也可能误伤有用调制成分，因此要先确定通带、阻带和采样率。

目前已有 63 抽头、面向 1 MS/s 波形的参考。RTL 每接受一对 I/Q 约需 66 个时钟的输入间隔，在 100 MHz 下结构上限约 1.515 MS/s，尚不是上板吞吐测量。

**该结构不能直接接当前 30.72 MS/s 输入。**需要决定采样率、正确的抗混叠抽取／重采样或更并行的硬件结构。不能只丢掉大部分样本就默认信号仍正确。

你可以参与：先比较滤波前后频谱、幅度误差和延迟；看到结构上限后，理解为什么“计算对”还需要“来得及”。

### 6.6 将算法变成 FPGA 电路

Python 的浮点结果要先转成明确的定点规则：输入、系数、累加位宽，何时舍入、怎样饱和。TestBench 是给电路自动送测试数据并检查结果的仿真程序，还要覆盖复位和下游暂停。

当前独立 FIR 增加一个转换状态后，100 MHz 内部综合时序估计由失败改为通过。完整原厂派生工程仍有负 setup 裕量，未通过部署验收。

WNS 是最差建立时间裕量。负数表示在当前约束下至少有一条路径来不及完成；要检查逻辑、布线与约束。综合估计、布局布线、接口时序与实际板端运行是逐层证据，不能互相替代。

你可以参与：阅读一次修改前后的时序和资源表，记录改了什么、数值是否保持、代价增加多少周期。当前工作的原厂固件与正在验证的新工程要分开记录。

### 6.7 建立数据集与训练模型

BPSK 每个符号有两种相位状态；QPSK 有四种；16QAM 有十六种幅度／相位组合。RRC 脉冲成形用于控制符号波形和频谱，符号率与采样率共同决定每符号采样点数。

当前 v1 合成数据包含 180 条独立母波形、1440 帧；三类和名义 10／15／20 dB SNR 平衡。训练／验证／测试按母波形分组，分别 1008／216／216 帧，避免同一长波形的相邻片段分到不同集合。

训练集用来学习参数，验证集用来选择模型，封存测试用来估计未见样本表现。第一次 CNN 诊断已看过原测试集，所以最终模型冻结后又生成独立新种子的 27 条母波形、216 帧作新测试。它仍属于同一合成分布，不代表真实 RF 泛化。

你可以参与：查看数据清单、画几帧波形、核对每类数量、按 SNR 和类别看错误。不要为了让准确率好看而把同源片段放入两边，或反复按最终测试调整参数。

### 6.8 在 ARM 上运行与比较量化

交叉编译是电脑为另一种 CPU 生成程序。当前 C 程序已经真实运行在 P201 Cortex-A9，输入为保存的合成数据。

CNN 有 115 个学习参数，输入 1024 对 I/Q，经去直流和 RMS 归一化后，完成卷积、ReLU、全局平均和三类输出。

| 实际实验 | 结果 | 应怎样理解 |
|---|---:|---|
| CNN FP32，新独立合成测试 | 200/216＝92.59% | 适用于已记录的合成条件 |
| CNN INT8 MAC，同一新测试 | 201/216＝93.06% | 小样本差异，不能证明量化提高泛化 |
| 已冻结传统基线，同一新测试，电脑计算 | 214/216＝99.07% | 当前合成分布下传统方法也很有竞争力 |
| ARM CNN FP32 平均耗时 | 0.563 ms | 含预处理和推理，不含采集／传输／界面 |
| ARM CNN INT8 MAC 平均耗时 | 1.109 ms | 这版实现更慢，候选仍保留 FP32 |

INT8 MAC 使用整数乘加，但预处理和部分重标度仍用浮点，不能称为完全整数推理。权重体积变小，也不意味着整个程序、内存和速度都按相同比例改善。

你可以参与：同时查看正确率、逐类错误、SNR、延迟和实现条件，理解为什么不能只凭“用了 CNN／用了量化”选择方案。

### 6.9 将模块接成系统

模块独立运行后，还需要匹配数据格式、采样率、符号率、时间和计算速度。当前 RX 的 30.72 MS/s 与模型 1 MS/s 训练条件不一致，单纯修改元数据不会改变真实样本间隔；正确重采样也不能自动解决所有符号率和信道差异。

接收、处理、推理和绘图应分开调度，缓存要有上限。系统应记录取得、分析、显示和丢弃的帧数，结果携带来源帧和配置，避免旧分类对应新波形。

你可以参与：观察开始／停止、断开／恢复、结果新鲜度、内存增长和保存内容，用明确步骤复现问题。

## 7. 不连板卡也能做的第一个小实验

目的：亲眼看到“频率位置由波形变化决定，功率由幅度平方决定”。它只生成模拟数据，不访问任何设备，不保存或修改原始采样。

在工程已有 Python 环境中手动运行下面代码即可。你可以让 AI 先逐段讲解，再运行。以下输出为理论预期；本手册的核验记录会说明代码是否经作者执行核对。

```python
import numpy as np

fs = 30_720_000.0
count = 1024
tone_hz = 960_000.0
time_s = np.arange(count) / fs
iq = 0.5 * np.exp(2j * np.pi * tone_hz * time_s)

frequency_hz = np.fft.fftshift(np.fft.fftfreq(count, d=1 / fs))
spectrum = np.fft.fftshift(np.fft.fft(iq))
peak_hz = frequency_hz[np.argmax(np.abs(spectrum))]
power = np.mean(np.abs(iq) ** 2)
half_power = np.mean(np.abs(iq * 0.5) ** 2)
change_db = 10 * np.log10(half_power / power)

print(f"块内覆盖时长: {count / fs * 1e6:.6f} us")
print(f"FFT 格点间隔: {fs / count:.0f} Hz")
print(f"谱峰: {peak_hz:.0f} Hz")
print(f"原始／半幅功率: {power:.6f} / {half_power:.6f}")
print(f"半幅后的功率变化: {change_db:.6f} dB")
```

理论预期：约 33.333333 us、30000 Hz、＋960000 Hz、0.25／0.0625、−6.020600 dB。此处故意选整频点单音并使用矩形截取，便于独立检查；当前真实监测使用 Hann 窗，不能直接比较两者未经说明的谱峰高度。

接下来一次只做一个变化：

1. 将 tone_hz 改为 −960000，观察峰位变为负频率、功率不变。
2. 只改变幅度，观察峰位不动、功率随幅度平方改变。
3. 将 count 改成 2048，观察覆盖时长加倍、FFT 格点间隔减半。

记录你改了哪个参数、先预期什么、实际输出什么。不要把这组模拟结果记为真实接收或 RF 电平实验。

## 9. 真实 RF 实验需要准备什么

### 9.1 先核对仪器，频率不必坚持 2.4 GHz

当前只是历史设置在 2.4 GHz。AD9361 官方标称 RX 范围为 70 MHz～6 GHz，但整板可用条件受匹配电路、固件和配置限制。不能把芯片标称范围当作整板每个频率都已经验收。

老师反馈：频谱仪约 9 kHz～3 GHz，信号发生器在 70 MHz 以下。设备型号、发生器是否包含 70 MHz 端点、已安装调制选件、输出电平尚未核对。

如果源能稳定输出到 70 MHz，可核对整板条件后评估低频端单音实验；如果上限明显更低，需要再评估适配方案。不能只凭“发生器 70M”就直接宣布适用或不适用，也不能将发生器最高正弦频率理解为任意调制下的可用带宽。

频谱仪主要用于观察和对照。其测量范围不代表能在同范围产生信号；如带跟踪源，须查具体型号的输出能力和工作方式。

### 9.2 同轴线与衰减器

同轴线用于受控传送射频。核对 50 Ω、频段、接头和损耗。衰减器按已知比例降低功率，核对衰减量、频段、接口与额定功率。

基本预算关系：

~~~text
接收口功率（dBm）≈ 源输出（dBm）− 衰减（dB）− 线损（dB）
~~~

例如 0 dBm 经 20 dB 衰减，忽略线损为 −20 dBm；这只是换算例子，不是本板建议输入设置。可调信号源若能可靠输出合适低电平，外接衰减器未必必需，仍需先确认板级推荐输入和峰值条件。

现有原理图表明板卡 TX 路径带功放，不能根据 AD9361 芯片输出或界面衰减读数猜测板卡 TX 端口功率。缺少板级电平依据时，不做 TX 直接接 RX。

### 9.3 分三步验收，先单音后调制

| 实验 | 受控改变 | 预期 | 必须保存 |
|---|---|---|---|
| 单音频率 | 已知源频率 | 谱峰按已知偏移移动；关闭源输出做对照 | 源型号／设置、接收配置、I/Q、谱峰误差 |
| 相对功率 | 固定 RX 增益，改变已知输出或衰减 | 未失真、明显高于噪声时，数字功率按预期变化 | 前后电平、增益、原始数据和误差 |
| 三类调制 | BPSK／QPSK／16QAM、已知符号率和成形 | 频谱及参数符合条件，模型可与隐藏真值比较 | 发送源记录、独立接收数据、分类结果与混淆矩阵 |

单音源可以做前两步；完整第三步需要对应调制功能或任意 I/Q 播放能力。普通低频函数发生器是否适用，要看真实输出频率和功能。

发送真值用于事后验收，接收分析和分类不能通过读取发送模式字段得到答案。同板自发自收共享时钟的条件也应在报告中注明。

## 11. 如何与 AI 共同完成研发，而不是只让 AI 代做

你负责提出目标、理解输入输出、提供物理条件、观察实际行为、确认结果含义。AI 可以负责读取资料、解释代码、编写／修改程序、运行已授权检查、整理证据。物理接线和仪器界面操作按当前分工由你完成；具体自动操作范围按当次授权。

每轮采用一个小闭环：

~~~text
讲清目标与原理
  → 固定输入与预期
  → 执行一个小任务
  → 查看真实输出
  → 对照独立依据
  → 记录通过／未通过／待验证
  → 决定下一步
~~~

算法开发使用：原理 → Python 黄金参考 → 理论预期 → 单元测试 → 目标实现 → 参考对比 → 上板 → 性能 → 记录。原厂软件启动、资料整理等任务不需要人为增加算法或 RTL 环节；不适用项说明原因。

你的学习不需要先通过考试。每完成一个小任务，尝试用自己的话写三句话：“我改了什么”“为什么会这样”“哪些结论还不能下”。AI 再结合证据纠正，这就是真正参与研发。
