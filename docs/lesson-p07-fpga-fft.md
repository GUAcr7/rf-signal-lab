# FPGA FFT 模块：用途、接口和本次验收边界

FFT 把一段 I/Q 从“随时间怎样变化”转换成“各个频率分别有多强”。电脑界面的频谱目前由 Python 计算；本次建立独立 FPGA 候选模块，让同一种计算以后可以放进可编程逻辑。独立模块通过不等于已经接到 AD9361 或 DMA。

## 1. 数据约定

| 项目 | 本次设置 |
|---|---|
| 工具与 IP | Vivado 2021.1，官方 XFFT 9.1，许可证 Included |
| 器件目标 | xc7z020clg400-2 |
| 变换 | 1024 点，正向，未缩放，自然输出顺序 |
| 算法结构 | radix-2 burst；先积累一块，再计算与输出 |
| 输入 | 实部、虚部各有符号 16 位整数，合计 32 位 AXI Stream |
| 输出 | 实部、虚部各有符号 27 位，各放在 32 位字段中，合计 64 位 |
| 相位系数 | 24 位，收敛舍入 |
| 工作时钟目标 | 100 MHz；板端实际时钟与完整集成尚未验收 |
| Hann 窗、PSD、ROI | 不在 FFT IP 内，须在前后级处理 |

输入 tdata[15:0] 为 I，tdata[31:16] 为 Q。输出有效实部为 tdata[26:0]，有效虚部为 tdata[58:32]；各自按 27 位二进制补码解释，不能把填充位当成额外精度。输出 tuser[9:0] 是频点编号 0–1023。TLAST 标记第 1024 个样本或频点。

配置口发送正向变换标志 1。数据口只有 valid 和 ready 同时为 1 才传输一个样本。下游 ready=0 时，上游必须保持 valid、数据和 TLAST 不变；不能只按时钟数推算已处理数量。

## 2. 怎样核对数字结果

Python 先生成整数 I/Q，用 NumPy 的双精度 FFT 得到数学参考；再使用当前安装包附带的官方位精确 C 模型，明确输入位宽、旋转因子、舍入和缩放，生成 TestBench 逐点比较的数据。

官方 C 模型把 16 位输入解释为 Q1.15，因此输入整数除以 32768；其未缩放输出乘回 32768 后还原为输出整数计数。这是模型接口的数值换算，不是标定输入电压。

11 组向量：零、直流、复数脉冲、正频率、负频率、偏离 FFT 格点的单音、随机 12 位 ADC 数据、16 位边界数据，以及三种已有合成调制波形。运行前约定 NumPy 对比最大复数误差不超过 64 个输出计数；实际最大约 18.861。零、直流和脉冲完全一致。

FPGA 仿真要求对位精确参考逐点完全相等，并检查频点顺序、TLAST、输出停顿期间稳定、部分输入后复位和复位后完整重放。不是只看波形图“差不多”。TestBench 保存每个输出和周期，Python 再独立检查整个 CSV。

本地输入来源和模型包哈希保存在 results/p07-fft-vectors-20261015T123025559103Z/verification.json；官方文件保留原版权和许可，不把它们称为自研 FFT。

## 3. 性能怎样解释

第一轮有意插入停顿的仿真通过 22 帧、22,528 个复数输出。无输入空闲／无输出背压的逐帧测试也通过，同一帧首个输入接收至最后一个输出接收为 7351 个 100 MHz 周期，即 73.51 μs；按孤立帧计算约 13.93 MS/s，未计系统接入开销。

这不能证明可以直接处理当前 30.72 MS/s 原始 ADC 连续流。后续必须明确在抽取后较低速率处使用，或换用更高吞吐结构，并同时检查 FIR、DMA、缓存和时钟域。当前已有 FIR 的结构吞吐约 1.515 MS/s，也不能直接挂在 30.72 MS/s 连续流上。

新增加的背靠背帧测试和独立布局布线结果以 [当天实验记录](experiments/exp-auto-20261015.md) 为准；工具执行尚未完成时不会提前标通过。

实际背靠背 burst 仿真已通过，两次各 11 帧／80811 周期，约 13.94 MS/s；相邻帧的输出结束间隔恒为 7346 周期，上游确实被 ready 反压并保持数据。因此不能只看到接口一拍能传一个数，就认为这个结构每拍都能无限接收。

同时建立了流水线结构作为另一候选：每级并行工作，增加资源以争取较高持续吞吐。其位精确 Python 参考最大误差约 23.3195 计数，符合相同 64 计数预设阈值。背靠背 22 帧全部位精确相同；包含启动时约 83.697 MS/s，稳定帧间隔 1024–1026 个时钟；输入间歇／输出背压、复位和重放也通过。它具备高于当前 30.72 MS/s 的模块吞吐余量，但还没有 ADC/DMA 系统接入。两种方案的独立布局布线资源如下。

| 独立模块 | LUT | 寄存器 | DSP | BRAM36 等效 | 内部 setup / hold 裕量 |
|---|---:|---:|---:|---:|---|
| radix-2 burst | 780 | 1570 | 8 | 3 | +4.735 / +0.068 ns |
| pipelined streaming | 3052 | 5802 | 22 | 4 | +3.755 / +0.003 ns |

注意：这些 OOC 结果没有绑定系统外部时钟缓冲位置，接口输入／输出延迟也未约束，尤其不能用很小的 hold 裕量承诺上板稳定。两个候选都必须在实际系统中重新约束、布局布线及验证，未生成或部署 bitstream。

## 4. 与现有 PSD 的衔接

为了与电脑参考一致，先对 1024 点 I/Q 乘同一周期 Hann 窗，再做 FFT。功率谱密度为 |FFT|² / (Fs × 窗系数平方和)，显示前才执行 fftshift 并转 dB。窗系数的定点位宽、乘法缩放、FFT 输出位宽以及平方后的累加宽度必须一起约定。

当前独立 IP 的输入没有 Hann 窗；不能直接拿它的矩形窗频谱与 GUI 的 Hann 频谱逐点比，也不能把未归一化 |FFT|² 写成 dBm。窗口乘法和 PSD 后处理尚待 RTL 开发、测试、时序及集成。

## 5. 可复用的文件

- experiments/p07_fft_vectors.py：生成双精度参考和官方位精确参考，不访问板卡。
- fpga/fft-vivado/prepare_fft.tcl：在新目录生成独立候选 IP。
- fpga/fft-vivado/tb_fft1024.sv：逐点自检、停顿和复位测试。
- fpga/fft-vivado/simulate_fft.tcl：运行 XSim，保留日志与 CSV。
- experiments/p07_verify_fft_simulation.py：独立检查保存的仿真结果与性能周期。
- fpga/fft-vivado/implement_fft.tcl：独立模块综合和布局布线，不生成 bit、不连接硬件。

采用“原理 → Python 参考 → 理论预期 → 自检仿真 → 模块时序资源 → 系统集成 → 上板性能 → 记录”。本次只推进到可单独验证的模块；完整 P07 尚未完成。
