## 2. 测量方法

对**实际发送的那批字节**（哈希逐支核对）做 Welch PSD：Hann 窗、`nperseg=4096`、50% 重叠 → **63 段平均**，频率分辨率 **7500 Hz**。然后用 `rfsig.bandwidth.occupied_bandwidth` 在载波附近 ±1 MHz 的分析带内求等尾 99% 带宽。

在数字域测而不是在仪器上测的理由：这些字节就是送进 DAC 的东西，是仪器读数必须对照的**数字参考**。仪器读数会额外包含 PA、线缆与仪器自身误差。

## 4. 关键纠正：`Rs×(1+β)` 不是 99% 带宽

初版脚本拿 `Rs×(1+β)=324 kHz` 当理论值，于是三种调制都显示 **−13% 偏差**，看起来像系统性错误。实际是**理论值用错了**。

RRC 滤波器幅度的平方是**升余弦谱**：

```
P(f) = 1                                    |f| <= (1-β)Rs/2
P(f) = 0.5[1 + cos(π(|f|-a)/(βRs))]         a < |f| <= (1+β)Rs/2      a=(1-β)Rs/2
```

- **支撑宽度** `Rs(1+β)` 是谱**降到零**的宽度，= 324 kHz
- **99% 能量带宽**明显更窄：解 `F(x)=0.99` 得 **279,998 Hz**

两者差 **44 kHz（13%）**，远大于测量误差，所以这个混淆会直接导致"看起来失败"。

**验证方式**：直接用数值积分构造升余弦谱并求 CDF，与闭式解在 0.5 / 0.65 / 0.8 / 0.9 / 0.95 / 0.99 / 0.999 七个点上对比，**最大差 0.0 Hz**。另有四个手算边界：
- `fraction=(1-β)=0.65` → `(1-β)Rs=156,000` ✓
- `fraction=1.0` → 支撑 `324,000` ✓
- `β=0, fraction=0.99` → `0.99Rs=237,600` ✓
- `β=1` → 小于支撑 `2Rs=480,000` ✓

### 4.1 交叉验证过程中发现并修正的两个我自己的 bug

1. **平坦区分支写成 `fraction×Rs/(1-β)`**，正确是 `fraction×Rs`。手算 `fraction=0.65` 时前者给 240 kHz、后者给 156 kHz，**错了 84 kHz**。是边界测试发现的。
2. **数值积分的 CDF 目标除了 2**。双侧 99% 对应的**单侧**能量份额就是 **0.99**（因为单侧总能量恰为双侧的一半），不是 0.495。除以 2 会让结果偏小约 2.4 倍。

两处都由"独立方法互相对照"暴露，而不是靠读代码发现。

## 5. 中心频率：三种估计方法的定量对比

同一 PSD 上同时算三种"中心频率"，与指令偏移（+960 kHz）比较：

| 波形 | 峰值法误差 | 谱质心误差 | 99% OBW 中点误差 |
|---|---:|---:|---:|
| BPSK | **+67,500 Hz** | +1 Hz | −1 Hz |
| QPSK | **+67,500 Hz** | −738 Hz | +202 Hz |
| 16QAM | **+52,500 Hz** | +3,250 Hz | −1,427 Hz |

**峰值法与后两者差了两个数量级**：峰值误差 52–67 kHz，是 99% OBW（约 280 kHz）的 **19–24%**。

这定量支持了 [EXP-TX-002](exp-tx-002.md) 第 4.1 节的方法学结论：

> 对调制信号，`Peak Search` / 取最大值点 **不能**用来估计中心频率；应使用**谱质心**或 **99% 占用带宽中点**。

项目 Python 侧 `p05b` 一直用 99% OBW 中点，**该选择被本次数据证实是正确的**，不是巧合。

**限制**：质心与 OBW 中点都依赖信号能量在带内的对称性；若存在强干扰或明显频谱倾斜，二者都会偏移（16QAM 的质心误差 3.25 kHz 就比 BPSK 大，反映其谱形更不光滑）。实际使用时应把"质心"和"OBW 中点"当两个独立估计，两者相差大时说明带内不干净。

## 6. 仪器交叉验证：三类调制全部完成

在 GPSA 模式下用 `Meas → 高级测量 → 占用带宽`（功率比 99%）。设置：**Center 2.450960 GHz / Span 1 MHz**（RBW 10 kHz、VBW 10 kHz、指数平均 10 次、801 点 = 1.25 kHz 网格）。

### 6.2 一个事先预测失败、但结论更有价值的结果

我事先预测仪器读数会**大于**数字域（理由是 RBW 更粗会糊宽边缘），预计 290–330 kHz。**实测三者都略小于数字域。**

而且"−1.08% 的系统偏差"这个猜想也被**推翻**：三支的偏差分别是 −1.08% / −0.05% / −0.40%，不是常数。所以这属于**每支波形各自的差异**（迹线平滑、噪声尾巴、边界判定），不是仪器系统偏差。

**正确记录方式**：两者一致到 ±1.1%，**不应声称某一方更准**。

### 6.3 三类调制在占用带宽上无法区分

| 现象 | 数值 |
|---|---|
| 仪器读数三者跨度 | **3,037 Hz = 均值的 1.08%** |
| 数字域三者跨度 | 2,410 Hz = 均值的 0.86% |

三类调制的**理论**占用带宽完全相同（`Rs×(1+β)` 支撑 324 kHz、99% 包容 280 kHz），实测也在 1% 内相同。

**这直接支持 [EXP-TX-002](exp-tx-002.md) §4.1 的判读**：调制识别**必须**依赖相位/星座信息，即必须接收 IQ。这解释了系统为什么必须有接收端，而不能停在"看频谱"。

### 6.4 传输频率误差：预测失败，并推翻了一个更早的结论

| 调制 | `传输频率误差`（仪器自算） |
|---|---:|
| BPSK | −1.829 kHz |
| QPSK | −4.767 kHz |
| 16QAM | −0.262 kHz |
| **均值** | **−2.286 kHz** |
| **峰峰值跨度** | **4.505 kHz** |

三者**真实中心完全相同**，读数却跨越 4.5 kHz —— 说明 **OBW 中心估计器本身有 kHz 级噪声**（迹线起伏导致边界判定抖动）。

这件事牵出更严重的问题：**我此前那条"本振偏 +2.5 kHz"的结论是错的。**

那两张单音照片是 **Span 10 MHz / 801 点**，标记只能落在 **12.5 kHz 网格**上。真实偏移 ±960 kHz = ±76.8 格；四舍五入到 ±77 格正是 **±962.5 kHz**。所以**即使本振偏置恰好为 0**，仪器也会显示 +962.5 / −962.5 kHz 和 1.925 MHz 的间隔：

| 项目 | 真实 | 零偏置时的网格显示 | 当时记录 |
|---|---:|---:|---:|
| tone-positive | 2,450,960,000 Hz | 2,450,962,500 Hz | 2,450,962,500 Hz |
| tone-negative | 2,449,040,000 Hz | 2,449,037,500 Hz | 2,449,037,500 Hz |
| 间隔 | 1,920,000 Hz | 1,925,000 Hz | 1,925,000 Hz |

**三个"证据"全部由量化复现。** 复算脚本 `experiments/p13_marker_grid_analysis.py` 输出 `RESULT: zero LO offset reproduces both readings and the 5 kHz gap`。

**修正后的频率结论**（三次仪器 OBW 中心读数：−1.829 / −4.767 / −0.262 kHz）：

> **观测到的事实**：三次读数的均值为 **−2.29 kHz**，极差 **4.5 kHz**。三者真实中心完全相同，读数却跨越 4.5 kHz —— 说明该估计器本身有 kHz 级噪声。
>
> **能声称的**：射频中心与理论值"在约 5 kHz 的量级上一致"。
>
> **不能声称的**：**不能把这个 5 kHz 当作精度上限或保证误差**。它是**三次观测的离散程度**，不是标定过的准确性指标；且分析仪频标未标定，它与板卡本振误差**无法分离**。要给出板卡的绝对频率精度，必须使用已知频率基准或共用参考时钟。
>
> 同理，`−2.29 kHz / 2.45 GHz = −0.94 ppm` 只是**观测到的平均偏移**，不是 ppm 级精度证明。

### 6.5 三次中心频率估计的最终对照

| 方法 | 网格 | 相对理论 2.450960 GHz 的偏差 | 可分辨能力 |
|---|---|---:|---|
| 单音峰值标记（10 MHz span） | 12.5 kHz | +2.5 kHz | ±6.25 kHz（**不足以分辨 2.5 kHz**） |
| 调制信号 Peak Search（10 MHz span） | 12.5 kHz | +67.5 kHz | **方法本身错误**，不可用于中心频率 |
| 仪器 OBW 中心（1 MHz span，三次均值） | 1.25 kHz | **−2.29 kHz**（三次跨度 4.5 kHz） | 受估计器噪声限制，非网格限制 |

## 10. 勘误（2026-10-17 独立审查后追加）

### 10.1 复数双边 PSD 被错误翻倍（已修正）

`experiments/p13_measure_obw.py` 里的 Welch 实现曾有一行：

```python
acc[1:-1] *= 2.0                      # one-sided   ← 错
```

输入是**复数 IQ**，其频谱不是共轭对称的，**不能套用实信号的单边约定**。这一行把除 DC 与末 bin 之外的所有 bin 翻倍，导致：

- 由 PSD 积分得到的总功率**约 2 倍**（守恒比 ≈2）
- 未翻倍的两个 bin（0 Hz 与 −7.5 kHz）**正好落在 ±1 MHz 分析带内**，带内出现局部半权重畸变

**修正**：改用 `rfsig.spectrum.welch_power_spectrum`（复数双边、功率归一化、由 `tests/test_spectrum.py` 的守恒测试覆盖）。

**量化影响**（必须如实记录，不要夸大也不要缩小）：

| 波形 | 修正前 OBW | 修正后 OBW | 差 |
|---|---:|---:|---:|
| bpsk | 282,710 Hz | 282,709 Hz | **−1 Hz** |
| qpsk | 282,380 Hz | 282,380 Hz | −1 Hz |
| qam16 | 280,300 Hz | 280,299 Hz | −1 Hz |
| 三个单音 | 22,050 Hz | 22,050 Hz | 0 |

**结论**：错误是真的，但对**已归档 OBW 数值**的影响只有 1 Hz（0.0004%），因为 OBW 是**带内比值**，而带内只有 2 个噪声 bin 未翻倍。**本文件第 3 节的 OBW 结论不受影响**，但方法本身必须改正 —— 因为它同时给出了 2 倍的总功率（3 dB），任何用到绝对功率密度的场合都会出错。

**新证据**：`results/p13-obw-20261017T103914Z/obw.json`，其中每个波形都记录了
`psd_power_conservation_ratio`（实测 **1.000000000**）、`psd_total_power`、`psd_window_weighted_power`、`psd_convention`。

**旧证据保留**：`results/p13-obw-20261017T044735Z/obw.json` 是修正前的原始归档，不删除、不覆盖。

### 10.2 "±5 kHz（±2 ppm）"被改写

原文把三次读数的极差 4.5 kHz 写成"一致到约 ±5 kHz（±2 ppm）"，读起来像一个**保证精度上限**。实际它只是**观测离散度**。已改为 §6.4 的表述：能声称"在约 5 kHz 量级上一致"，不能声称那是精度上限。
