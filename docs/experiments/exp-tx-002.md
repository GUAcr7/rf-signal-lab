### 3.1 定量结论：本振偏置 +2.5 kHz

> ## ⚠️ 本节结论已被推翻（2026-10-17 03:5x 追加）
>
> **"+2.5 kHz 本振偏置"是错的：那三个数字完全可以用网格量化解释，不需要任何本振偏置。**
>
> 那两张照片是 **Span 10 MHz / 801 点**，所以标记只能落在 **12.5 kHz** 的网格上（`10e6/800 = 12500`）。真实偏移 ±960 kHz = **±76.8 格**，即不是整数格。四舍五入到最近的整格是 **±77 格 = ±962.5 kHz**。
>
> 于是：**假设本振偏置恰好为 0**，这台仪器会显示
>
> | 项目 | 真实值 | 网格上最近的整格 | 当时记录的读数 | 一致 |
> |---|---:|---:|---:|---|
> | tone-positive | 2,450,960,000 Hz | 2,450,962,500 Hz | 2,450,962,500 Hz | ✅ |
> | tone-negative | 2,449,040,000 Hz | 2,449,037,500 Hz | 2,449,037,500 Hz | ✅ |
> | 两峰间隔 | 1,920,000 Hz（153.6 格） | 1,925,000 Hz（154 格） | 1,925,000 Hz | ✅ |
>
> **三个"证据"全部由量化复现，零偏置就够。** 复算脚本：`experiments/p13_marker_grid_analysis.py`。
>
> **为什么当时会误判**：我把"误差大小相等方向相反"和"间隔恰好扩大 5 kHz"当成物理特征，但没有先检查读数本身的分辨率。**±2.5 kHz 只有网格步长（12.5 kHz）的 1/5，在这个分辨率下根本不可分辨**。这是"在测量分辨率以下解读数据"的典型错误。
>
> **正确的说法**：这两张照片能证明的频率精度上限是 **±6.25 kHz（半个网格步长）= ±2.6 ppm**，无法给出 1 ppm 量级的结论。要测到 kHz 级必须**减小 Span**（后来 BPSK 的 OBW 测量用 1 MHz / 801 点 = 1.25 kHz 网格，才够精细）。

下面这段是**被推翻的原始推理**，保留以便追溯当时错在哪里。

两个偏移的误差**大小相等、方向相反**，间隔误差正好 **+5.0 kHz**。这曾被解释为本振偏置的特征：

```
f_measured = f_LO_actual + f_digital_offset
若 f_LO_actual = 2.45 GHz + 2.5 kHz：
  正偏移误差 = +2.5 kHz      负偏移误差 = -2.5 kHz
  两峰间隔   = 1.92 MHz + 5.0 kHz      ← 与实测一致
```

**该推理的缺陷**：它没有考虑标记读数的量化步长，而上述所有数字都能由 12.5 kHz 网格在**零偏置**下产生。

## 4. 三类调制：都能发射，但频谱仪分辨不了它们

| 波形 | 归档照片 | Marker 读数 | `mean_I2_Q2` |
|---|---|---|---|
| BPSK | `results/p13-session2-bpsk-solo2-20261017T0152/spectrum-bpsk-shaped-block.jpg`（sha256 `1a6a7c05…`） | 2.45 GHz / −58.20 dBm（**不在包上**） | 26,896,695 |
| QPSK | `results/p13-session2-qpsk-solo2-20261017T0205/spectrum-qpsk-shaped-block.jpg`（sha256 `7695155f…`） | 2.45 GHz / −57.87 dBm（**不在包上**） | 28,594,213 |
| 16QAM | `results/p13-session2-qam16-solo2-20261017T0220/spectrum-qam16-marker-on-signal.jpg`（sha256 `54c9d79e…`） | **2.450875000 GHz / −33.71 dBm（在包上）** | 18,668,821 |

三张照片都能看到**中心右侧约 1 格的宽包**，宽度约 0.3–0.4 格。理论占用带宽 `Rs×(1+β)` = 240 kHz × 1.35 = **324 kHz**（±162 kHz）= 10 MHz 扫宽下 **0.324 格**。实测与理论相符（25 kHz RBW 会把边缘糊宽一点）。

### 4.1 三条必须写清楚的判读

**① 频谱仪分辨不了 BPSK / QPSK / 16QAM。** 三者符号率与滚降完全相同，理论占用带宽都是 324 kHz，包络形状几乎一样；**区别在相位结构**，频谱仪只测包络。要区分必须**抓 IQ 再做星座/AI 识别**——这正是需要接收板的原因，也是任务③不能停留在"频谱照片"层面的理由。

**② `Peak Search` 对调制信号给出的不是中心频率。** 16QAM 那张里 Marker 落在 **2.450875000 GHz**，比预期中心 2.450960000 GHz 偏 **−85 kHz**——虽然仍在 ±162 kHz 带内，但**不是中心**。原因：调制信号在带内是随机起伏的，`峰值搜索` 找的是最高采样点，位置随机。

> **对任务②的直接含义**：`峰值搜索` 只适合**单音**。做"中心频率估计"必须用**谱质心**或"99% 占用带宽的中点"等方法。项目 Python 侧 `p05b` 已用 99% OBW 中点（`ROI_lower/upper → midpoint`），这个选择是对的；**不要用 peak 位置代替中心频率**。

**③ 峰值 dBm 与平均功率不是一回事。** 16QAM 的 `mean_I2_Q2` 比 BPSK 低 1.58 dB，但照片上包顶电平（−33.71 dBm）与 BPSK 接近——因为 25 kHz RBW 是在测**带内功率密度**，不是信号总功率。**不能用包顶电平排"哪个平均功率高"**。

> **⚠️ 该结论严格绑定本次配置**：`tone-positive`（数字峰值 512 = 满量程 1/4）、TX 数字衰减 **−10 dB**、TX LO 2.45 GHz。**换波形的数字幅度或改小 TX 衰减都必须重算**，不可据此直连。

> 另：`−10 dB` 是**数字衰减读数**，不等于 dBm；接头与线缆损耗未标定。故本预算用于**保守判断"会不会打坏接收机"**，不是绝对功率标定。

## 6. 本轮修复的两个工具缺陷

1. **上传包 `SHA256SUMS` 被写成 CRLF**（Windows Python `write_text` 用 `os.linesep`）。BusyBox `sum` 不剥 CR，把 `\r` 当文件名一部分 → 板端 8 项全部 `FAILED`。
   - 现象：`sha256sum: can't open 'arm/arm-tx-source': No such file or directory`
   - 修复：`experiments/p13_build_upload_bundle.py` 改为 `write_bytes` 显式写 LF，并**断言不含 CR**；重建后 731 B（原 739 B），板端 **8/8 OK**。
   - 板端就地修复（省一次 3 分钟上传）：`tr -d $(printf '\r') < SHA256SUMS > SHA256SUMS.lf`。
2. **`tr -d '\\r'` 是错的**：PowerShell 把 `\\r` 原样传给 shell，`tr` 删掉的是字面 `\` 与 `r`，739→727 B（每行少一个 `r`）。必须用 `$(printf '\r')` 生成真正的 CR。两次字节数（739→731）恰好差 8 = 行数，正好印证每行删了 1 个字节。
