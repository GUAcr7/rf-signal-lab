# P36：完整 IQ 留存与连续性验证合同（离线规划，未上板执行）

- 日期：2026-10-21。
- 本文只检查既有代码和原始记录，新增本文；没有操作串口、板卡或界面，没有修改现有源文件。
- 目的：在当前 RF/显示合并验证之后，以最小改动补齐完整 IQ 证据；不重做已通过的稀疏诊断，也不把新的合并候选视为已验收硬件。

## 1. 现有证据允许的结论

P35 的 [16 缓冲原始报告](../../results/p27-smoke-20261020t160826z/report.json)确实检查了 libiio 0.20、RX1 两通道、4 B/帧、65536 帧/refill、RF 属性前后相同及正常释放。但每缓冲只保存前 8192 帧中的 1024 帧，完整性标记明确为 false。程序前缀的 P27 是复用工具名，不能误当成另一启动的结果。

[取消/重建报告](../../results/p33-rx-cancel-board-20261020t160708z/report.json)支持有限 8 轮取消和恢复，不证明 ADC 时间连续。[HW-019](exp-hw-019-memory-diagnostic-and-build-readiness.md)的 512 缓冲记录也只保存 1.5625% 样本；122.87 MB/s 是搬运并提取少量前缀的观测，不是完整保存、分析和显示吞吐。

[HW-018](exp-hw-018-review-and-streaming.md)已发现四通道 16 大缓冲有 11 处非周期跳跃；改为 RX1 后 16 缓冲没有检出，但源周期为 131072 帧，整周期缺失不可见。落点已确认是 tmpfs，不能重新把缺口归因于 SD。保留三个不同结论：

| 结论 | 最小证据 | 禁止引申 |
|---|---|---|
| 返回的完整缓冲已保存 | 每次返回长度/布局正确，全部字节复制、归档、哈希一致 | 不等于所有 ADC 样本都被返回 |
| 已知周期源位置一致 | 可信匹配且相邻窗口模周期增量正确 | 不等于无整周期缺失，也不等于独立 BER/AI |
| 指定采集路径和时长无丢样 | 明确采样位置的独立序号/计数或等效无歧义证据，所有检查通过 | 不自动覆盖别的配置、时长、显示负载或丢失位置 |

## 2. 第一项交付：单独的有限完整缓冲采集器

保留现有 [arm_rx_diagnostic.c](../../embedded/arm_rx_diagnostic/arm_rx_diagnostic.c)作为稀疏工具；新增独立完整采集器和独立 schema。不能只把 `STRIDE` 改为 1：现有 `malloc(count*KEPT*4)`、复制边界和元数据仍是前缀语义。

首次只采 16 缓冲，采用以下固定合同：

1. 复用已经验证的 libiio 0.20 动态加载、设备按名字发现、RF 属性前后读回、BIST 关闭和错误清理。只启用 RX1 的 `voltage0/voltage1`，明确 I/Q 顺序；不沿用四通道解析，不把读取退出后的 scan cache 当采集中配置证据。
2. 创建缓冲前预分配并预触页 `blocks*65536*4` 字节及小型时间戳表；验证乘法溢出和分配失败。整个采集使用同一 context、同一 IIO buffer；不逐块销毁/重建，不逐块启动外部读数程序。
3. 每次 refill 后复核返回字节 262144、step=4、Q 指针=I+2、end-I=262144；任何不符即失败并保留已完成块的实际数量。将 **全部 262144 原始字节**立即复制到独占目标槽位，再 refill。不能只保存 IIO 缓冲指针，下一次 refill 可能重用其内存。
4. 热循环仅做 refill、布局检查、整块复制和单调时钟打点；不打印逐块日志、不写文件、不做 FFT/匹配/绘图、不传串口。先保留原始 packed `le:S12/16>>0`；掩低 12 位并符号扩展放到停止后或电脑解析，未定义高 4 位不参与幅度分析。原始字节与转换后字节分别命名、分别哈希。
5. 有限次数完成后先停止并销毁 IIO buffer，再读 RF 配置、写原始文件和元数据；拒绝覆盖已有结果。若采集失败，报告非零退出码及 `completed_blocks`，不得把不足次数补零或补重复数据后标通过。取消不属于首个最小实现的必需项；若加入，复用 [arm_rx_cancel.c](../../embedded/arm_rx_cancel/arm_rx_cancel.c)的普通线程取消及 join 规则，signal handler 只置标志，不能在线程仍活动时销毁 context。
6. 运行结束后由外部控制脚本独立检查 buffer/scan 空闲、内核新增错误及 RF 配置；归档全部原始数据到电脑，验证板端/电脑 SHA256 与精确长度。保留失败输出，不能以重新运行成功覆盖失败会话。

| 缓冲数 | 完整 IQ 帧数 | 原始数据 | 名义样本时长（30.72 MS/s） |
|---:|---:|---:|---:|
| 16 | 1,048,576 | 4 MiB | 34.133 ms |
| 64 | 4,194,304 | 16 MiB | 136.533 ms |
| 512 | 33,554,432 | 128 MiB | 1.092267 s |

16 通过才考虑 64；512 必须先检查当前可用内存、CMA、内核 DMA 队列和显示占用。完整保存到 tmpfs 会与采集区产生第二份内存占用，512 不能只按 128 MiB 估算峰值。不能仅凭板卡 DDR 总容量决定可分配量。

## 3. 元数据必须将字节、软件时间和 ADC 时间分开

每次会话保存 boot_id、运行 PL/DTBO 身份、程序 SHA、libiio/内核版本、RF 前后属性、实际启用通道及格式/scan index、每帧字节数、缓冲帧数、内核队列设置（读不到则明确 unknown）、所需/完成块数及错误。知道已知发送源时另绑定源文件 SHA、源周期、发送守卫和实际配置，不据旧 boot 的 TX 记录假设它仍在运行。

每块保存 `block_index`、目标文件字节偏移、实际字节数，以及相对 `CLOCK_MONOTONIC` 的 `refill_start/end/copy_end`。该序号只表示程序接收顺序；这些时间是软件观测，不是 ADC 时间戳。采样时钟计数未提供时，`adc_first_sample_counter=null`、`hardware_gaps="unknown"`、`lossless_proven=false`。建议使用更窄的 `complete_returned_buffers_saved=true`；若沿用 `complete_stream_saved`，必须明确其仅指已返回缓冲的字节完整性，避免误读为 ADC 连续。

65536/30.72e6=2.133333 ms 是名义缓冲时长。refill 返回可能消费已经排队的块；一次调用慢于或快于该值均不能独立推导丢样。单次观察总时长接近名义值也不能关闭连续性问题。记录 copy 延迟及总体搬运速率，用于定位性能，不代替样本位置证据。

## 4. 复测按依赖推进

**A. 不发射的完整留存 smoke。** 当前合并候选先按其自身启动合同验收；稳定后运行 16 缓冲完整采集，验证长度、格式、完整回传和释放。这里可验收存储路径，不能验收已知源/连续性。采集器的最少离线测试覆盖：两通道正负 12 位解析、每块首尾字节和不同内容、大小/步幅/短返回拒绝、失败只保存已完成块、拒绝覆盖和清理；用实际 C 的模拟 IIO 接口测试，不只测一个 Python 复写。

**B. 复用现有受守卫保护的已知周期 BPSK。** 重新认旧板/boot、校验源及安全配置后才由主任务安排一次有界发射；不增加功率，不为了此项改动新板 RF/PL。对完整块复用 [capture_continuity.py](../../src/rfsig/capture_continuity.py)的已知源匹配，保留每个原始窗口索引。除整块外用首/中/尾或滑动重叠窗口定位内部异常；没有检查的位置明确不覆盖。弱相关或匹配失败的窗口不能删除后比较远邻，应把邻接边界标为 unverified。沿用相关度门限 0.99 和 ±1 帧估计容差，同时报告实际位置、残差及 CFO。跨未知边界先分段，不让 FIR/PLL 直接贯穿；该轮最多结论为 `modulo_consistent` 或 `detected_jumps`。

**C. 需要宣称无丢样时再补独立位置证据。** 不把现有 131072 周期源或软件 block_index 升格为独立计数。有两条可选路线，先选择成本较低的一条，不要求两条同时重建：

- 在采样路径加入明确采样点上的硬件计数/序号和溢出观测；计数要在可能丢失的位置之前按每帧采样事件递增，并与 IQ 原子绑定到数据流/可验证块元数据。只在 CPU 读取某寄存器的墙钟时刻取一次计数，或只给被 DMA 接受的帧编号，会漏掉上游丢失。若只保留块首/尾计数，应明确只能验证这些边界和跨度，不能自动排除块内重复与缺失抵消；要得到更强结论需适当密度序号/全路径溢出证据。附加字段增加带宽，必须重新测量。
- 使用具有经验证唯一位置的长非重复发送序列，或带递增帧号、CRC 和已知符号的流，并保存全部原始 IQ。必须界定可辨识的最大缺失长度和符号/采样定时容差；一个更长但仍循环的 PRBS 仍有整周期歧义。RF 源解码能证明的范围不应混写为每一个 ADC 样本的硬件计数证明。

第一版完整采集不必等待 C 的 FPGA 或发送器改造；A/B 的真实数据可以直接支持 C 的选型和缺口定位。

## 5. 如何区分缺口和主机延时

| 观测 | 正确判定 |
|---|---|
| refill/串口/文件回传慢，但独立序号显示完整连续 | 排队或主机处理延时；不能仅凭延时宣布丢样 |
| 强可信源位置或独立计数在相邻数据中跳跃 | 采集路径出现不连续；即使总用时接近名义值仍成立 |
| 周期源模差为零，缺独立序号 | 仅模周期一致，整周期缺失仍待验证 |
| 相关度低、信号质量不足或配置不一致 | 连续性无法判定；不能强行归类为丢样或通过 |
| 文件大小/SHA 都正确 | 传输完整；不能证明 ADC 样本没有在更上游丢失 |

已有证据不能唯一确定跳变发生在内核排队、消费者调度还是其他位置。不要再以有符号模差求负丢样量，或用一个良好 EVM 块证明长流正常。

## 6. 完整显示管线是其后的独立验收

完整留存合同成立后，再让采集生产者写有界内存队列、分析消费者计算指标，屏幕仅按需要更新图像；屏幕刷新无需跟每个 IQ 块同速。记录队列最高占用、显式丢弃数量/位置和停止原因。队列加深只能吸收突发延迟，不能解决平均消费速度不足。

先单独采集，再加入分析，再加入屏幕，使用同一采集配置比较完整性和延迟。若最终目标只要求间歇快照，允许据实验收该模式；若降低采样率来满足实时链路，记录实际硬件读回和新的带宽合同，不将旧 30.72 MS/s 结果沿用。未知缺口时瀑布图使用块索引或明确断点，不能伪造连续 ADC 时间轴。
