## 目标与起点

将既有收发/校准逻辑整理为固定入口，先验证能实际停止、重新开始、新校准和发送切换。依据START-HERE/P58交接及新版工作流程推进，不复用旧boot或旧校准。

初始只读检查：`results/p59-status-20261025T024117839684Z/report.json`。旧P201为FTDI序列号210203859289B/COM9，boot `97f90856-4479-4846-bd04-a39a6978384d`；新板CH340/COM8，boot `48a30fb3-e240-4fee-824d-a46f975d5358`，两板taint均0。

新板本次上电已自动启动接收，首读约376秒/735次更新，状态CALIBRATION_REQUIRED且校准令牌为空。旧板TX DMA为0，DDS scale全0、raw全1；本轮先受控选择数字零源，读回raw/scale全0。没有把初始raw=1且scale=0直接当作已发射，也没有把数字零等同绝对RF静默。

旧板实际只有控制台ttyPS0，驱动读回UART1 mmio0xE0001000；新增外设UART尚未出现在运行系统。根文件系统为RAM，另有jffs2挂载，本轮未向持久存储部署程序或波形。

## 实现

- 新增`host/board_control.py`及`run-board-control.cmd`，提供status、stop、source-off、prepare-source、start、calibrate、send、demo。
- 自动依据已知FTDI序列号与唯一CH340查找候选端口，再核对Linux身份。不会探测蓝牙串口或Pluto gadget控制台；端口缺失/歧义时拒绝继续。
- 新增`src/rfsig/board_session.py`，核对当前boot、完整timeout argv、DMA/scan、进度、退出与AI状态；避免用旧文件或复用PID误判正在运行。
- 新建RX仅在干净停止后执行：保留旧RAM目录，复制并校验原P56 monitor/run，仅启动应用，不重载硬件或修改持久启动。
- 恢复冻结seed2315/peak256源包至旧板RAM，使用现有USB网络、逐文件SHA和原guard输入检查；源缓存绑定本次boot，发射前再次读文件与guard哈希。
- 新校准先验证旧源关闭；令牌由本次会话生成，单音校准不读取真实调制标签。发送类型仅由控制器作为验收答案保存，不传入接收分类器。
- 新入口有Windows本地互斥锁；参数非法、状态不一致、RF/内核门禁失败时拒绝操作。原板端发射guard保留5～60秒有界输入约束。

当前预设仍为Fs30.72MS/s、Rs240ksym/s、偏移+960kHz、TX峰值256/-10dB、TX/RX LO2450MHz、RX手动0dB，保持既有接线。没有新增可自由调节的射频参数，没有训练或替换模型。
