# EXP-HW-014：定位并消除“块间星座质量跳变”

- 日期：2026-10-17；性质：旧真实数据复算 + 新的双板射频对照实测 + 软件修复。
- 来源：用户提交 EXP-PROBLEM-LOG 中的问题截图，授权实际修复并留实验记录。
- 本记录取代 HW-012/HW-013 关于“必须换仪器/采 1 秒才能继续”“处理链已完全排除”的结论。历史记录与原始采样保留。
- 当前结论：**已定位旧文件在 DMA 缓冲边界的源时间跳跃；单个 65536 点缓冲方案已经在板上通过重复验证。** 不把它扩大为长期无丢样流采集。

## 1. 实际问题是什么

旧命令：

```sh
iio_readdev -b 4096 -s 65536 cf-ad9361-lpc > /tmp/bl.bin
```

文件长 524288 字节、SHA256 与板端完全一致，只能证明 65536 个四通道帧已正确回传，**不能证明这 16 个缓冲在 ADC 时间上连续**。原来的 8192 点分析块会跨越两个 DMA 缓冲，整块 RRC 卷积和载波环于是跨过缺失的时间。

新的诊断不用猜调制类型：对照实际发射的 256 档文件，逐个 4096 点缓冲拟合一个时延、一个频偏和一个复增益。参考波形重新生成后先与实际交付的 IQ 文件逐字节核对；接收文件也重新与串口 base64、板端 SHA256 三方核对。

旧 BPSK 的源波形起点：

```text
文件偏移        0   4096   8192  12288  16384  20480  24576 ...
源周期内位置 42971  47067  51164  55260  60399  70726  80532 ...
```

前面相邻位置约增加 4096，随后多出 1043、6231、5710 等采样。它们不是定时环在 2.13 ms 内自然漂移几十个采样，而是文件拼接处对应的源位置跳跃。QPSK/16QAM 的旧文件也各检出 **12 个不连续边界**；各缓冲与真实发射参考的相关系数均 >0.99。

**边界**：源序列周期 131072 点，额外前进量只能按周期取模；不能据此给出精确丢样总数，也不能排除恰好整周期的损失。现有证据定位到采集缓冲边界和拼接处理，未定位到内核某个函数，更没有证明 AD9361 或板卡损坏。

## 2. 排除方法上的错误

原结论“功率平稳，所以不是干扰或接收链问题”证据不足：时间跳跃可保持功率和频谱正常。原结论“理想波形能跑，所以真实数据处理链没有问题”同样不成立：无间断的参考没有覆盖有时间缺口的输入。

还发现三个独立的软件问题：

1. 很短的片段用“最大平均输出功率”盲选定时，可能因具体符号模式选到错误相位。旧数据的诊断改用**已知源对齐**，不把结果当盲同步能力。新长快照另用最大功率法验证，未提供已知定时。
2. QPSK/方形 16QAM 的标准星座四阶矩相位与 BPSK 不同；统一按零相位去旋会给 QPSK 留下 45° 错位。现按实际星座表的矩相位对齐。
3. 判决反馈环直接拿 ADC 大数值对单位星座判决，环路行为随信号电平改变。现先在环内归一化，输出保持原幅度，并增加三类调制的增益不变性测试。

旧数据每缓冲独立处理并使用已知源定时后的最差 EVM：

| 调制 | 最差缓冲的已知符号 EVM | 后半段判决错误 / 检查符号数 |
|---|---:|---:|
| BPSK | −37.12 dB | 0 / 176 |
| QPSK | −37.50 dB | 0 / 176 |
| 16QAM | −36.29 dB | 0 / 176 |

每个 32 符号缓冲舍弃两端各 5 符号，保留 22，16 个缓冲共 352 符号；没有补造丢失样本。相关证据：`results/p22-gap-resolution-20261017T131247Z/report.json` 和同目录图。

## 3. 板上对照实验

### 3.1 复核与固定条件

- 实测串口：旧 P201 COM9，新 TLZ7xH-EVM COM8；这是本次观察，不是永久端口约定。
- 旧板 boot_id：`f2c4a78e-b10c-4060-95a9-d55aca93b468`；程序、256 档三支波形仍在本次开机的 `/tmp`。
- 新板 `/etc/board-mode=rf`，`ad9361-phy` 正确，未占用采集工具。
- TX/RX：Fs=30.72 MS/s，LO=2450 MHz，RF 带宽 18 MHz；TX gain=−10 dB、port A；RX1 manual/0 dB、A_BALANCED。
- 复用已实测的双板接线和 256 档配置；没有提高电平，没有写 RF 属性，没有重启或更换位流。
- 每类调制只进行一次 **30 秒限时发射**；每次都记录 `CYCLIC_PUSH_SUBMITTED`、到期、DDS 零源读回、释放缓冲以及返回 0。采样后再串口回传，不在回传时持续发射。

### 3.2 单变量干预

每种调制依次采三份，每份 65536 帧、524288 字节：

```sh
# 对照：16 个 4096 点缓冲
iio_readdev -b 4096 -s 65536 cf-ad9361-lpc > small.bin
# 干预：一整个 65536 点缓冲，独立重采两次
iio_readdev -b 65536 -s 65536 cf-ad9361-lpc > big1.bin
iio_readdev -b 65536 -s 65536 cf-ad9361-lpc > big2.bin
```

正式工具使用唯一文件名和防覆盖检查；上面的短名仅用于说明。改变的是接收缓冲长度，没有通过调功率、调增益或换参考来“改善”结果。

### 3.3 结果

| 调制 | 小缓冲检出的跳跃边界 | 大缓冲两次跳跃边界 | 大缓冲 EVM，第一次 / 第二次 |
|---|---:|---:|---:|
| BPSK | 12 | 0 / 0 | −37.82 / −37.74 dB |
| QPSK | 12 | 0 / 0 | −38.07 / −37.96 dB |
| 16QAM | 12 | 0 / 0 | -37.23 / -37.30 dB |

大缓冲全段先做源位置连续性核验，再运行下变频、RRC、丢弃两端各 640 点、盲选整数定时相位和星座相位对齐。每段保留 **502 个符号**。EVM 用实际发射的符号序列和一个复增益拟合，不是把接收样本替换成参考。

后半段判决：增益只用前半段拟合，再检查后 251 符号。**频率、源位置估计仍使用整段已知源相关**，所以这不是严格独立的统计测试集，也不是 AI 准确率或通用 BER 验收。

## 5. 验收与限制

| 验收项目 | 结论 |
|---|---|
| 旧数据为什么出现大幅块间质量差异 | 通过：缓冲边界源时间跳跃 + 跨边界处理被实际定位 |
| 不更换设备能否改善 | 通过：三类各两次大缓冲全部通过；对照各 12 处跳跃 |
| 完整 Python 回归 | **780 passed，46.80 s**；`results/p22-verification-20261017T1323/pytest.log`、`pytest.xml` |
| 最终资料与样本复核 | `results/p22-final-verification-20261017/manifest.json`；样本再次校验 SHA，文档本地链接检查见同目录 document-links.json |
| 旧数据、板端 hash、回传是否保留 | 通过：原件不改，新证据单独归档 |
| 长时间实时无丢样 | **待验证**；本轮只接受单缓冲 2.133 ms 快照 |
| 真正 AI 识别 | **待验证**；已知序列诊断没有训练/验证新模型 |
| 同时射频与屏幕显示 | **未实现**；现有两份 PL 位流仍互斥 |

上游 [libiio 0.20 官方 readdev 实现](https://analogdevicesinc.github.io/libiio/v0.20/libiio/iio_readdev_8c-example.html) 是 refill 后输出、再 refill 的循环，不能把“进程退出 0”解释成跨缓冲 ADC 连续性证明。这是方法依据；本板具体丢失发生在驱动、缓冲供给还是调度中的哪一步，仍需计数器/时间戳诊断。

下一步按依赖：先冻结已验证的单缓冲接口与元数据，再为长期采集加入生产者/消费者、丢帧计数或硬件序号及吞吐测试，之后采独立 RF 数据集，划分训练/验证/测试并记录 SNR，最后推进显示与射频 PL 合并及 AI 部署。不要把更多 PLL 调参当作修补缺失时间的办法。

## 6. 本轮遇到的非工程失败

- 第一次 QPSK 回传误填了不存在的时间戳路径，程序在打开串口前报 FileNotFoundError；改为采集程序实际输出的路径后继续，没有增加发射或覆盖文件。
- 新 CLI 测试首次遇到 Windows 子进程错误输出使用本地编码，已让测试子进程显式使用 UTF-8；完整回归无警告。
- 旧数据初次短缓冲盲定时仍出现差 EVM，没有把结果删掉当作成功；改为明确标记的已知源诊断，再用新长快照的盲定时独立验证。
- 记录汇总脚本第一次在生成最后的文件哈希清单时混用了相对/绝对路径而退出；状态与记录已成功写入，随后仅恢复只读核验和清单生成，没有回滚或重复发射。
