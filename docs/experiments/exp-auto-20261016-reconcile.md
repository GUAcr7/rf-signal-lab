## 4. 本轮发现并修正的一个**自己引入的**错误（重要）

在用脚本打包时，我一度**凭记忆写出了 qpsk 与 qam16 的 sha256**，只有前 16 位是从工具输出复制的，其余是编造的：

| | 我写的（错误） | 实际 |
|---|---|---|
| qpsk | `fd56491f068881c5` **`b4b2f0e0b5c7e0e9a2f1b8b3c4d5e6f7a8b9c0d1e2f3a4b5`** | `fd56491f068881c5` **`c315fc4fba41bfd165b0e3e25419d66755e66c372081cee9`** |
| qam16 | `85f8df7f3f5e9866` **`c9e0e4b1a2d3c4b5e6f708192a3b4c5d6e7f8091a2b3c4d5`** | `85f8df7f3f5e9866` **`678df225da3f3421ecc453891284b12ca9ad67895be26efc2`** |

前 16 位相同、之后全错 —— **只看前缀根本发现不了**。这正是"看起来对的伪造数据"：包还是能打出来，上传后板端 `sha256sum -c` 才会失败，而那时已经在实验台前浪费一次会话。

**修正方式**：改为**从已有 manifest 读取哈希**，再对磁盘实际字节重算比对，两次都相符才写入 tar；脚本里不再出现任何手抄哈希。已加入的运行时断言使这类错误在打包阶段直接抛错，而不是等到板端。

**教训**：哈希必须程序化获取并双向校验，**任何"我记得是……"的哈希都不可接受**。这与本记录第 2 节处理的历史记录错误同类——数字必须有可指认的来源。
