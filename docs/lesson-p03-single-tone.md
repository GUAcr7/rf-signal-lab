# P03 入门：用一个已知单音检查收发链路

单音可以想成“只有一个音高的声音”。我们先在电脑里造出频率已知的波形，再让板卡接收它。因为答案事先知道，频谱峰如果出现在别的位置，就能定位收发链路或 I/Q 处理中的问题。

数字 I/Q 中，I 和 Q 是同一采样时刻的两个数。一个理想复数单音可以写成：

`I[n] = A cos(2πfn/fs)`，`Q[n] = A sin(2πfn/fs)`，因此 `x[n] = I[n] + jQ[n]`。

这里 `fs` 是每秒采多少**对** I/Q，`f` 是相对发射调谐频率的基带偏移，`A` 是本次 Python 实验的归一化幅度。I 与 Q 交替变化，可以把它想成一个指针在平面上转动；把 `f` 改为负数，转动方向反过来。只用一条实数余弦会同时出现正、负两个频率峰，I/Q 使方向能够区分。

本次黄金参考取 `fs = 30,720,000` 复数样本/秒、`N = 1024`、`f = +960,000 Hz`、`A = 0.5`。FFT 把一帧拆成频率刻度，刻度间隔是 `fs/N = 30,000 Hz`；因此峰应落在第 `960,000/30,000 = 32` 个正频刻度。若用 `|FFT|/N` 表示幅度，理想峰值是 0.5。将偏移改为 +1,920,000 Hz，峰应移动到第 64 个刻度；改为 -960,000 Hz，峰应落在负频一侧。这些结果已通过离线单元测试。

**基带频率**不是空中的射频中心频率。理想情况下，如果日后把发射和接收都调谐到 2.400 GHz，并通过已核算的射频环回发送 +0.960 MHz 单音，接收基带应在 +0.960 MHz 附近看到峰，对应射频约 2.400960 GHz。这是后续上板的理论预期，当前尚未发射，也未实测射频峰。

`A=0.5` 只规定电脑里生成的相对数值，不能直接解释为发射功率或接收电压。实际接收幅度会受发射增益、线缆/衰减器、接收增益和模拟链路影响。射频环回之前必须核对板卡接口和电平，不直接把 TX 与 RX 相连。

## 暂无环回线时：板内 RX 测试音

AD9361 还能在芯片内部的 **RX 数字数据出口**放入一个测试单音。可以把它理解为：不从天线听声音，而是在交给 FPGA 的数据流里插入一个事先知道音高的“电子试音”。当前采样率为 30.72 Msps，选择 `fs/32`，理论音高就是 0.96 MHz；1024 点 FFT 仍应在正频第 32 格看到峰。[ADI 的 BIST 说明](https://analogdevicesinc.github.io/linux/drivers/iio-transceiver/ad9361/#bist-tone)给出了 RX 注入命令 `2 0 6 0`，其中 `2` 表示 RX 端，`0` 表示 `fs/32`，`6` 表示低于满量程 6 dB，最后的 `0` 表示不屏蔽通道。

这种实验能检查 RX 数字接口、I/Q 样本读取、文件保存和频谱坐标。它绕过了天线、射频输入和 ADC，**不能证明真正收到空中的信号，更不能代替 TX→RX 射频收发验收**。测试音的样本幅度是板卡原始计数，不能与 Python 黄金参考的归一化 `A=0.5` 直接比较。测试完要关闭注入，并读回关闭状态；本实验不使用会向 TX 端发射的环回模式。[ADI 对数字与射频环回的区分](https://analogdevicesinc.github.io/linux/drivers/iio-transceiver/ad9361/#bist-loopback)说明了这两种路径的差别。
