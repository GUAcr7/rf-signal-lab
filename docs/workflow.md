# 工程与验证约定

## Git

Git 保存有说明的工程版本。主分支 `main` 保留已复核的阶段成果；每个小实验使用一条短期分支，例如 `level0/bpsk-map`。

```powershell
git switch -c level0/bpsk-map
# 完成讲解、实现、独立预期和测试，并更新实验记录后：
git status
git diff
git add src tests experiments docs
git diff --cached
git commit -m "feat(level0): add verified BPSK symbol mapping"
```

上面是以后完成实验时的示例，本次不能提前执行该功能提交。一次提交围绕一个可描述的变化；先查看暂存差异，再提交。合并前由另一位队员复现。两人协作以后再配置远程仓库，本次仅建立本地仓库。

## Python 测试

- 测试文件命名为 `tests/test_<功能>.py`，统一通过 `python -m pytest` 运行。
- 先用固定的短序列，预期值来自手算、解析公式或独立实现。随机测试作为补充。
- 固定并记录随机种子、Python 版本、依赖版本、参数和数据形状。
- 每个函数先写输入输出契约，包含单位、形状、数据类型、非法输入与空输入处理。
- 浮点数按误差容限比较；容限需解释来源，不能为了测试通过随意放宽。
- 测试日志和大图可留在 `results/`；精简结果、复现命令和关键证据存入实验记录。
- 新模块引入新的测试义务；没有测试文件时，不把测试命令的退出解释为验证成功。

## FPGA（到对应阶段再教学）

每个 RTL 模块必须有 TestBench，包括输入激励、预期输出、自检和失败退出。IP 封装模块同样需要 TestBench。覆盖复位、正常输入、边界输入、数据有效与暂停行为；涉及多时钟时单独分析。

先用浮点模型确定算法，再用与硬件位宽、舍入和溢出规则一致的 Python 定点模型生成测试向量。定点模型用于逐位比对，同时保留相对浮点参考的误差统计。

每次优化填写硬件模板，保存器件型号、工具版本、约束、资源报告、时序报告、延迟和吞吐率。比较必须使用同一输入和条件，并区分模块计算时间与包含传输的系统时间。

## AI（到对应阶段再教学）

每个模型必须填写模型模板，记录数据集构成、每类数量、SNR 范围及分布、训练/验证/测试划分、随机种子、输入预处理、模型结构、训练配置、准确率及量化结果。

按独立原始波形或采集会话分组划分，避免相关片段跨集合。量化校准与调参不能使用测试集。不能用同一批数据既选择模型又报告最终测试表现。评估总体、逐类、逐 SNR 表现，并保留错误示例。

当前目标是 Zynq-7020 的 ARM CPU 推理，没有硬件 NPU。电脑上可运行并不代表板载 ARM 环境兼容：先核验操作系统、处理器架构、推理库、算子和内存需求，再冻结网络结构。模型训练在电脑完成，板端推理速度必须实际测量。

## 完成判定

每个实验记录区分“已实现”“已验证”“待做”“本阶段不适用”。缺少硬件测试时明确记录待做。任何实际结果都附命令和证据；未测数字写“未测”，不能用目标值或宣传峰值代替测量。

实验记录的代码提交号填写被测代码版本；记录本身可在随后的文档提交更新，避免要求一份文档引用包含自身的提交号。
