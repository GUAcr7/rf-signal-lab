# P201 独立串口屏：队员学习与交付任务书

> 2026-10-25历史标记：正文保留早期“P201屏幕显示接收结果”的任务背景。当前用户决定这块新T1屏用于旧P201的**发射控制**，接收显示由新TLZ7xH原屏承担。后续按[新版工作流程](workflow-next-20261024.md)及[T1发送控制屏接入准备](design/tjc-source-screen-20261025.md)执行；本文件不作为当前接线、参数和已完成状态的依据。

## 目标与边界

负责把 **P201 板端算出的结果**送到 4.3 英寸 T1 串口屏，使演示时电脑可以断开，屏幕仍能随真实接收数据更新。屏幕只负责显示和可选的触控操作；FFT、参数估计、AI 判断仍由主系统完成。先做参数和识别结果，再做简化的 I/Q 时域曲线、频谱；不要把模拟结果说成真实射频实测。

当前选中的商品文字是“T1 系列 4.3 寸电容屏模块”，**尚未核实发货的完整型号**。厂商资料中接近的型号是 TJC4827T143_011C_I_P20，但规格、电压和引脚必须以实际订单型号及随屏资料再次核对。现有项目指南 P11 仍写电脑端完整界面；独立屏是本次新增的展示要求。瀑布图是否也必须在这块小屏上显示，要单独实测确认，不能因为屏幕局限就默默删除原项目功能。

## 先学会这些概念

1. **串口 UART**：双方按同一速度逐字节传数据。要分清波特率、8N1 格式、TX/RX/GND 和电平；“5 V 供电”不等于“串口可接 5 V 信号”。P201 的现有电脑调试串口不能直接当屏幕插座。
2. **智能屏/HMI**：先在厂商编辑器里做好页面、数字框、文字框和波形控件，再由板端发送“改某个控件的数值”命令。屏幕不接收 30.72 MS/s 原始采样流，而接收少量图点、参数和识别结果。
3. **图的含义**：I/Q 是接收信号的两列数字；时域图看它们如何随采样点变化；频谱图看各个频率有多强。绘图前要把实际数值缩放到屏幕控件允许的范围，并保留坐标、单位和缩放规则。
4. **显示链路**：ARM 程序组织结果和串口命令，PL 可以提供独立 UART 出口。学会区分“电脑模拟发送成功”“板端字节输出正确”“接上真屏持续刷新”三个不同证据。
5. **数据有效性**：每帧带序号或时间；失联或数据停止时显示过期/断开。AI 标签和置信度只有在真实模型推理完成后才标记为“实测”；之前必须标注“演示/模拟”。

## 推荐交付顺序和验收

| 阶段 | 队员要做的事 | 可以交付、可验收的证据 |
| --- | --- | --- |
| A. 型号与资料 | 核对实际屏幕完整型号、供电、串口电平、引脚顺序、接插件、厂家编辑器和串口协议；画屏幕接线草图，但暂不接 P201。 | 型号照片/规格链接、引脚表、供电方案、协议摘要。型号未确定时不得写“已兼容 P201”。 |
| B. 独立屏页面 | 在电脑上用厂商编辑器做首页：中心频率、占用带宽、相对功率、BPSK/QPSK/16QAM、置信度、连接状态；另做简化 I/Q 与频谱页面。先用编辑器模拟器，再用 3.3 V USB-TTL 模块给实屏发送固定测试数值。 | 页面工程与可重编译/下载文件、屏幕照片或录像；断开电脑数据线但保持供电后，界面能独立启动。参数变化和失联提示可见。 |
| C. Python 黄金参考 | 写一个小程序：读取现有保存的 I/Q，算出**已由项目算法确认**的显示量，把一帧结果编码为屏幕命令；另写假数据模式专测文字、数字和曲线。给命令结束字节、数值范围、缩放、异常输入写单元测试。 | 输入文件、测试报告、命令字节样例、实屏显示与 Python 预期逐项对照。P03 数字 BIST 单音可用来检查频谱图位置，但不能冒充真实射频或调制训练集。 |
| D. 板端接口可行性 | 查 P201 原理图、现有固件和 `pzp201` HDL 工程；先确认原工程能在实际工具版本下重建，记录板型/芯片/固件关系。再核实 J19 是否有**未占用的 3.3 V PL 管脚两根**可用于 UART TX/RX，以及板端程序如何访问该接口。此项未通过之前不接屏。 | 原工程重建记录、管脚对照表、与现有功能无冲突的约束修改方案。只要无法证明重建与恢复，板卡直连仍记“待验证”。 |
| E. FPGA 串口与板端发送 | 按项目原有顺序做：原理 → Python 字节黄金参考 → 理论预期 → 单元测试 → UART RTL/IP 及 **TestBench** → 字节对照 → 上板 → 性能 → 文档。ARM 程序按固定速率取最新结果，发送屏幕命令并处理返回字节；先发固定 TEST，再回放文件，最后才接实时结果。 | RTL/TestBench 日志、串口抓包与 Python 对照、资源/时序/延迟/吞吐率记录、板端日志。不能只有“屏幕亮了”的照片。 |
| F. 断开电脑联调 | 由持板队员在核对供电和电平后接线。断开电脑数据连接，保留 P201 与屏幕各自所需电源；用板端真实采集结果连续更新，测试停止/恢复采集、重启和失联。 | 连接图、独立运行录像、所显示结果的来源及配置、刷新率与连续运行记录、故障恢复记录。未完成真实射频或 AI 模型时对应栏明确“待验证”。 |

第 B/C 阶段只需队员自己的电脑与屏幕，可以与主队的 P03/P05 并行。第 D/E 阶段须和负责 FPGA 的队员共同评审，不能让主系统 FIR/FFT 的负责人空缺。

## P201 直连时的关键检查

- 现有 J15 调试口承担电脑登录，不能未经改造就假定它是屏幕专用口；J19 是 PL 扩展排针，不等于已经存在 UART。固件包中可找到 `plutosdr-fw/hdl/projects/pzp201/` 的 `system_top.v`、`system_constr.xdc`、`system_project.tcl` 等，**存在源码不等于当前板卡镜像已能无损重建**。
- 目标屏若确认为厂家候选型号，资料标为 5 V 供电、3.3 V TTL 串口；需核实实际型号。屏幕由符合规格的稳压电源供电，P201 与屏共地，板端 TX→屏 RX、板端 RX←屏 TX。不要把 5 V 电源接进 PL 信号脚。
- 若用厂商波形 `addt` 批量传点，屏幕有准备/结束返回信号，故建议设计双向串口并实测握手。波形点通常是 0–255 的显示值，不是原始 ADC 数值；发送前记录映射范围和单位。`115200 8N1` 的理论线上限约 11.5 kB/s，实际可达刷新率仍须测量。
- 必须记录最终硬件是否需要额外 3.3 V USB-TTL 调试器、屏幕专用 5 V 电源、对应线束；这些是开发/供电配件，不是树莓派。最终演示若目标是无电脑，不能依赖电脑持续转发数据。

## 小屏最终应显示什么

最小可用页面：接收中心频率、占用带宽、相对功率、识别类别、置信度、连接/更新时间。第二页面：抽点后的 I/Q 波形与频谱，能随接收数据变化，标清横轴及单位。瀑布图是原项目目标，先做屏幕上彩色滚动显示的可行性实验；若性能或控件不足，提交实测结论和替代屏方案给团队决定，不能直接宣布“已实现”。

整机完成的验收不是单看屏幕：屏上的数值要与同一帧的 Python/板端结果对应；改变输入后可见更新；停止或断开后不能继续伪装实时。至少记录一次稳定运行的实际刷新率、误帧/丢帧、重启恢复、供电和接线信息。

## 第一个工作周的三件事

1. 拿到完整 SKU 和规格，做一页“供电—引脚—串口电平—协议—资料链接”记录。
2. 用厂家编辑器完成静态页面；用电脑 3.3 V USB-TTL 给真屏发送数字和识别文字，验证离线启动与刷新。
3. 和 FPGA 负责人一起只读检查 `pzp201` 源码、P201 原理图和当前镜像，形成两根可用管脚及原工程重建的验证计划；这一步先不改板卡。

学习时一次只推进一个小功能：先讲清含义，再做黄金参考、预期、测试、实现和记录。每个结论只填“通过／未通过／待验证”，附实际证据位置。
