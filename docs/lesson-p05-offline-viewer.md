# P05 小任务：先用已有文件验证分析窗口

## 这一步做什么

此前频谱、瀑布图、功率和带宽是各自独立的小实验。现在把它们接成一个电脑窗口，检查同一帧的图和数字能否对应、按钮能否正常操作。暂时不接入板卡，不依赖 Vivado 或外部信号源。

“帧”就是从连续样本里取出的一小段。本窗口每帧 1024 点。FFT 使用这些点算频谱；平均 I²+Q² 使用这些原始点算数字功率；在指定频带累计谱功率，得到 99% 区间宽度和中点。瀑布图保留最近 96 帧的谱。

“Hop”是下一帧起点往后挪多少个样本。模拟文件 Hop=512，所以相邻的 1024 点帧重叠一半。每次显示的 Source time 是该帧中间样本在原文件中的时刻。

窗口定时器希望每 100 ms 播放一帧，只是让人看清变化。模拟文件实际只有 96 ms 信号，却可以慢放约 19 秒；实际 GUI 速度还要测量。不能把播放时长写成连续射频采集时长。

## 数值怎样看

- **Mean I²+Q²**：本帧原始数字功率。模拟恒幅 0.5 单音应约为 0.25；相对于固定参考 0.25 为约 0 dB。
- **99% region width**：当前选定频带中的 99% 谱功率区间。Hann 窗的有限时长单音约为 **2.94 kHz**；理想无限长单音只有一个频率，窗口使有限数据的谱有宽度，这个数不是发射器的已校准射频带宽。
- **Region midpoint**：上述区间中点。在单频区间应约为 -128/+128/+256 kHz。跨切换处的一帧包含两个频率，中点和带宽变化正常。
- **ROI**：选定分析频段。它限制“统计哪一段谱”，不是自动识别目标的功能。
- **AI: NOT CONNECTED**：模型还没有接入，没有类别/置信度结果。

模拟时域图只画当前帧前 64 点，方便看清 I/Q，两条曲线不代表两路天线。所有参数与 FFT 仍使用完整 1024 点，保存也保留这 1024 点。

频谱单位是 dB 相对于 `1 输入单位²/Hz`，不是 dBm。取对数时仅为显示把极小值截到 1e-16；NPZ 仍保存原始线性谱。瀑布图颜色范围在当前来源内固定并有色条，超过范围仅颜色饱和，不修改数据。

## 旧真实文件的第二轮验收

首轮 GUI 操作通过后，再关闭模拟窗口，双击 `run-analyzer-record.cmd` 并点击 Start、Save。现有记录仅 1024 点、约 33.33 µs，因此是 **1/1 帧并马上 FINISHED**；只出现一行谱是正确的，不是持续接收失败。不能复制旧数据来制造长瀑布图。

应看到 Fs=30.72 MS/s、FFT=1024、Hop=1024、格距 30000 Hz、ROI=±9 MHz，平均功率约 1046.9 计数平方。固定参考是这份完整文件自身的平均功率，因此相对值 0 dB 是定义带来的结果，不代表测到了某个射频功率基准。

宽度约 17.6258 MHz、中点偏移约 0.105178 MHz，是未知输入谱在 ROI 内的统计结果。没有目标真值，不能确认某种调制或已知载频。LO 加中点也只是带条件的坐标换算，实际频率方向/精度仍需受控 RF 验证。
