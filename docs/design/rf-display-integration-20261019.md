## 合并必须解决的差异

| 项目 | RF 工程 | 显示工程 | 合并要求 |
|---|---|---|---|
| 器件 | XC7Z100FFG900-2 | 相同 | 继续使用精确器件型号 |
| UART1 MIO | 48–49 | 12–13 | 以实际 TLZ7xH 板级配置及已运行启动链为依据，不能照搬 RF PS 初始化 |
| MIO 0–15 电气设置 | 多项 1.8 V | 多项 3.3 V | 查板级原理图/已有 PS 初始化；禁止自动用 RF 配置重建启动包 |
| GPIO EMIO 宽度 | 64 | 1 | 合并 RF 控制 GPIO 与触摸中断，保持驱动使用的位号 |
| FCLK0 / FCLK1 | 100 / 200 MHz | 100 / 200 MHz | 核对实际配置、连接、复位与 Linux 时钟设置 |
| FCLK2（配置值） | 50 MHz | 250 MHz | 不可同时继承两值；查实际消费者后重新分配 |
| 以太网配置 | 100 Mbps / 25 MHz | 1000 Mbps / 125 MHz | 保持实际载板 PHY 与启动配置 |
| DMA DDR 端口 | ADC→HP1，DAC→HP2 | VDMA→HP0 | 可作为候选分配；仍需评估时钟、仲裁与 DDR 总吞吐 |
| 外部显式 PL 引脚 | 53 个 | 64 个 | 当前 XDC 没有直接 PACKAGE_PIN 重复；这不等于已通过 IO bank 电压/差分对/时序检查 |

共有 **108 项双方显式 PS 参数值差异**，包括派生值和描述字段，并非 108 个独立故障。单方省略项必须用 Vivado 的完整 CONFIG 读回或实际 PS 初始化补齐。

RF 的 64 位 EMIO 是 Linux GPIO 编号的基础之一。显示原厂只有 1 位；合并时如果直接缩减，会使 AD9361 reset/控制位映射失效。MIO8 风扇也须保持现有启动行为；读回 0 已知不能独立判断风扇是否旋转。

补充只读实测：`results/p29-ps-readback-20261019T090944Z/` 保存 10 个 SLCR 字的读数，没有写寄存器。[生成代码对照](../../results/p29-ps-generated-comparison-20261019t091727z/report.json) 中，显示 PS-init 在这 10 字上匹配 5 个；RF 在有写入的 9 字上匹配 2 个（FCLK3 未写，不能判匹配）。显示的 4 个 FCLK 控制字都匹配，部分 MIO 不匹配。**两份 PS-init 都不能直接认作当前完整板级初始化**；Linux 可能在启动后修改寄存器，本检查也未识别实际 BOOT 输入。保留当前可工作启动链，按原理图/实际初始化补齐 PS 配置，不能只因显示 demo 能运行就照搬其所有 PS 设置。

两套资料的预编译 FSBL/BOOT.BIN 分别相同，证据在 `results/p29-ps-boot-baseline-20261019T085558Z/`；源码包中找到 `ps7_init.c` 并不证明它是预编译 ELF 的真实构建输入。

SPI/GPIO 的可复用连接已核对源码：RF 使用 **SPI1 / 0xE0007000**，显示触摸使用 **SPI0 / 0xE0006000**，不必将二者并接到同一个 SPI 控制器。RF 顶层实际使用 EMIO[46:32] 连接射频控制、[47:48] 控制 up_enable/up_txnrx；触摸输入是 EMIO[0]。保留 64 位总线后可以规划独立位号，仍需给新顶层加仿真、明确其余输入的接法，并核对设备树。

## 地址与中断候选表

| 外设 | 已有地址 | 范围 |
|---|---|---|
| AD9361 AXI | `0x79020000` | 64 KiB |
| RX DMA | `0x7C400000` | 4 KiB |
| TX DMA | `0x7C420000` | 4 KiB |
| 显示 VDMA | `0x43000000` | 64 KiB |
| TPG | `0x43C00000` | 64 KiB |
| 视频时钟 | `0x43C10000` | 64 KiB |
| VTC | `0x43C20000` | 64 KiB |

这些外设窗口没有直接重叠。RF 原厂 DMA 中断接 concat In13/In12。合并时重建一份明确的 concat→IRQ_F2P 对照表，核对 Linux GIC 编号；不能仅把两个 concat 输出连在一起。

显示原厂中断为 VDMA MM2S→In0、S2MM→In1、VTC→In2、TPG→In3，和 RF 的 In12/In13 位置分开；这只是候选，必须维持 PS IRQ 配置和实际 Linux 编号一致。

## 显示迁移的专门限制

显示 BD 在 2021.1 中升级了 Clocking Wizard 5.4→6.0、VTC 6.1→6.2、TPG 7.0→8.1。原厂模块引用源没有主动修改。

- v2 迁移已通过 `validate_bd_design`，无锁定 IP。门禁随后因 22 项关键区域元数据差异退出 32，明确要求人工/程序审查，而不是当作迁移完成。
- 14 项 DDR/MIO 总线边界从空白变为明确位宽；6 项外部像素时钟增加 148.5 MHz/相位/域注释；2 项已重建 AXI 互连内部地址别名消失。PS7 配置与 PS 外设地址窗口在前后快照中未变化。后续只准许这些精确元数据差异，不能放宽所有检查。
- **8 项 VTC 默认时序参数发生变化**：VBLANK 水平起止 1920→960，VSYNC 水平起止 1920→1004；同时升级引入 `fid_in/fid`、`sof_state` 等端口。它们不能因框图检查通过就宣称功能等效。须核对新旧生成参数、运行时 AXI 编程及新增输入连接，并用仿真或受控上板验证实际显示时序。
- 独立综合只证明可编译，不证明 LCD 画面/触摸/模式切换与旧版一致。

## 已验证的显示时钟补充

原厂 `parity_flag` 每个像素时钟上升沿翻转，经过 BUFG 输出二分频时钟；默认约束漏掉这个派生时钟，导致 21 个无时钟端点、65 个内部未约束端点。

- [自检 TestBench](../../fpga/tb/tb_display_half_clock.sv) 对原厂未改 RTL、原生 UNISIM BUFG 模型检查 35 个完整周期、3 次异步复位（74 个有效输入周期），通过。只覆盖时钟/复位，不冒充完整 RGB 映射或面板功能仿真。
- [约束源](../../fpga/constraints/display_lvds_half_clock.xdc) 声明已有时钟的 /2 派生关系，不删除路径或改变周期；已加入 E 盘短路径副本并完整重综合。
- 实测 master=6.734 ns、derived=13.468 ns；no_clock=0、unconstrained_internal_endpoints=0。[结果](../../results/p29-display-clock-20261019t091430z/report.json)。原厂源码不变，原基线 DCP/报告保留。
- 更完整的约束揭示综合 WHS=-1.221 ns；56 个外部输出仍缺时延约束。这不是时序通过，仍需布局布线与外部接口依据。RF 的 CDC 报告也存在需审查的 Critical 项，不能把报告生成成功当作全部验收通过。
