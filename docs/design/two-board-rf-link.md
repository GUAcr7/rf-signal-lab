# 双板收发与显示接入方案

日期：2026-10-16。用户提出的候选方向：旧 P201 做信号源，新借的带屏板做接收与显示。本文件是实现计划，不是实物连通证明。

> **2026-10-16 晚状态更新**：旧 P201 作为信号源的部分**已从"候选"变为"已实际执行"** —— 已做 3 次限时射频发送（3 s / 5 s / 5 s，+960 kHz 与 +1.92 MHz 单音），TX 端口确认走 **TX1**（程序里端口 `A`），频谱仪上出现主峰。详见 [EXP-TX-001](../experiments/exp-tx-001.md)。
>
> **但本文件中以下限制全部继续有效**：
> - **未接第二块板的 RX**，也**不得在完成电平核算前接**（第 41–46 行的验收顺序不变）。
> - **发射功率尚未定稿** —— 唯一归档的频谱照片上标记不在主峰上，`-24.43 dBm` 那次读数无图支撑。**衰减量必须等功率定稿后才能算。**
> - 屏幕与新板系统仍未验证。
>
> 本文件第 11 行原写"未创建实际 TX buffer、未改 RF 参数、未发射"，**其中"未发射"已被取代**；"未改 RF 参数"仍然成立且已由程序日志 `rf_settings_written=false` 独立确认。

## 已确认与尚待确认

旧板是既有实测的 PUZHI PZSDR P201，原厂运行系统、IIO、采集程序及波形参考可复用。新资料是 TLZ7xH-EVM + AD-FMCOMMS3-EBZ，支持 Zynq-7045/7100，但实物尚未连接核实。详细来源见 [新资料审查](new-board-ad9361-review-20261016.md)。

两板都用 AD9361，并不意味着 FPGA bitstream、引脚、供电、Linux、库版本和屏幕驱动相同。产品目录已确认TLZ7xH-EVM有HDMI/LVDS/背光及12V DC@3A标签，但仍缺具体实物/插头极性/屏pinout和驱动对应，不能因此直接上电改线。保留老师现用系统；不把 P201 的 bit/BOOT/设备树写到新板，也不照案例重新制卡覆盖现有屏幕系统。

本次提供的是离线发送文件和有限时发送程序候选。未创建实际 TX buffer、未改两板 RF 参数、未发射。

## 数据与接口分工

```text
旧 P201：保存的已知 I/Q → 本地限时循环 DMA → AD9361/板载 PA → TX1
                                    ↓
                       按实际功率选衰减器 + 50 Ω 同轴线
                                    ↓
新板：RX1A → AD9361 → 原厂 FPGA/IIO → ARM 分析/模型 → 实物屏幕
```

图中的 TX1/RX1A 是资料中的候选端口，接线前仍核对实物丝印、PA 和实际驱动端口选择；不凭照片位置映射。发送口不用天线进行本轮有线核验，未用的发送口按板厂说明处理。软件停止 DMA/选择数字零不等于射频绝对静默，仍可能存在本振泄漏。

## 三套准备好的波形条件

| 配置名 | 采样率 | 符号率 | 数字搬频 | 用途与限制 |
|---|---:|---:|---:|---|
| existing30m72 | 30.72 MS/s | 240 ksym/s | ±960 kHz 单音；调制 +960 kHz | 对应旧历史采样率，当前实际读回仍待做；不是现有模型精确训练条件 |
| planned4m250k | 4 MS/s | 250 ksym/s | ±500 kHz 单音；调制 +500 kHz | 计划配置，未写硬件；接收后搬回零频、滤波和4倍抽取才到1 MS/s、4点/符号 |
| planned4m125k | 4 MS/s | 125 ksym/s | 同上 | 计划配置，未写硬件；接收适配后可到1 MS/s、8点/符号 |

每套包含单音正/负、BPSK、QPSK、16QAM；RRC beta=0.35，span=10，周期卷积避免全卷积尾巴重复造成接缝。峰值是 I 或 Q 分量有效 DAC 码512，存储码乘16；它不是射频 dBm，也不保证三类平均功率相同。循环波形不是新的独立训练集，切出的重复帧不能跨训练/测试集合制造泄漏。

不能仅让两个板都保持默认值就期待接收：资料默认 TX LO=2.45 GHz、RX LO=2.4 GHz，相差50 MHz，超过当前采样窗口。完成接线与电平核算后再选共同/匹配的本振；在接收带内应满足

`f_received_baseband = f_TX_LO + f_wave_offset - f_RX_LO`。

4 MS/s 仅是便于接入现有1 MS/s模型的候选。需要分别核查两块板的时钟/FIR与合法速率并写后读回，不直接套用 pyadi-iio 的 sample_rate setter：本机该 setter 会连带配置芯片 FIR。旧板TX0还经过可旁路的8倍插值，**DMA文件采样率可能是PHY采样率的1/8**。当前程序只支持旁路，必须读到DAC DMA Fs=PHY TX/RX Fs=文件Fs，否则停止，不切active/GPIO。当前发送程序只核对既有设置，不自动调谐或改FIR。

## 实际受控 RF 验收顺序

1. 核实实物/供电、保存老师现有屏幕基线、两个系统版本和设备列表。新旧板接同一网络时确认 IP 不冲突；设备按 URI、型号、序列号分别钉死。
2. 确认旧板 TX SMA 在所用频率/数字幅度/增益下的峰值输出上限，包含 PA；确认新板 RX 推荐输入范围。取得衰减器最小衰减、额定输入功率、频段、接口与线缆参数。不要将2.5dBm芯片绝对最大当推荐目标。
3. 计算 `RX_peak_upper = TX_peak_upper - attenuation_min - cable_loss_min`，检查明确的余量以及衰减器额定输入。没有线缆损耗依据时不拿估计损耗抵消风险。补齐 link-review.INCOMPLETE.json 中真实证据；模板故意不能通过检查。
4. 首次只发有限时单音，分别保存源关闭、源开启、正偏移、负偏移的 RX 原始 I/Q、配置、发送日志、SHA和接线证据。根据双方频率精度及FFT间隔预先声明误差容限。验证峰随源移动而移动，排除零频直流/未知环境峰。
5. 固定 RX 增益，在无削顶、未落入噪声底条件下改变已知衰减/输出电平，验证相对功率变化。AGC数据不直接做这一验收；绝对dBm另标定。
6. 分别发送三种调制，保存每次源波形标识、bit/符号/符号率/RRC/载频、TX与RX日志、实际RX文件。完成频偏/速率适配后才统计真实分类。发射端标签是期望信号，不代表接收块一定捕获了有效目标；仍要筛选并保留拒绝理由。
7. 先保留电脑显示作为对照，再把经新系统ABI重编译的分析/模型和屏幕程序接上。最后验收上电、源启动/停止、屏幕更新和脱离电脑运行。

## 屏幕单独的接入门槛

资料里的 IIO Oscilloscope 在 Ubuntu 电脑运行；射频 PL/DTB 未发现显示链路。镜像里存在 Qt/Xorg 和 linuxfb 等插件，只证明有软件基础。需要实物型号、屏幕型号/接口、主板基础资料、现用显示工程和系统；如果屏幕原本工作，先保留其驱动/设备树/PL，再判断是否与射频工程共存。

新资料镜像为 glibc2.23/libiio0.20/Qt5.7.1；原板实测为glibc2.28/libiio0.24。分析源码可复用，不能未经ABI核查直接复制现有ARM可执行文件。当前新TX程序针对旧P201的0.24库，不部署到新板。

## 不依赖当前硬件的已完成准备

- 周期波形、逻辑DAC/存储码格式、独立周期卷积对照和包读回。
- 离线哈希/元数据/重新生成核验、端口功率预算和缺失资料拒绝。
- ARM有限时循环发送候选、板端本地截止/信号处理/资源清理；实际发送验收单独记录。
- 接收/显示候选迁移点与资料清单。已有原厂采集链继续保留；无需为制作信号源先加载时序未通过的新FPGA。
