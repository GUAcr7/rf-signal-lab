## 2. 当前屏幕的职责

本屏接旧P201，用于发送端操作：选择单音/BPSK/QPSK/16QAM、选择已验证预设、定时发射、停止和查看源状态。新板原有屏幕继续负责接收分析与AI结果。发送端标签只作验收答案，不向接收分类器提供类别。

原`display-terminal-team-task.md`属于早期“P201显示接收结果”方案，保留为历史。当前执行范围以新版工作流程和本文件为准。

第一版页面规划（480×272，尚未编译成HMI）：顶部显示RF SOURCE与连接/运行状态，中间四个信号选择按钮、预设参数与时长，底部应用、开始、停止。区分“已选择”“已应用”“正在发送”，板端确认后才显示应用/运行成功。上电默认待机。

参数先沿用已验证档位：LO2450MHz、偏移+960kHz、Fs30.72MS/s、Rs240ksym/s、峰值256和TX -10dB；不因能在屏上输入数值就放开未验证的射频范围。LO加偏移的2450.960MHz属于名义频率，不是仪器实测值。

屏幕数值变量按32位整数处理。2.45GHz的Hz值超过有符号32位上限，频率输入可用kHz整数2450000并标明单位，显示时转换为MHz文本；不将2450000000直接塞入当前非负int32命令接口。

## 3. 官方串口协议核对与已准备代码

依据本轮归档的官方get、返回格式和printh文档：

- 板端可发送`get n0.val`等命令；官方C示例在指令后附三个0xFF字节。
- 勾选控件发送键值后，按钮事件按0x65、页面ID、控件ID、事件和三个0xFF返回；按下为1、弹起为0。
- 数值get回复以0x71开头，携带四字节小端值及结束符；数值载荷本身可能含0xFF，不能对全部二进制回包简单按FF FF FF切分。
- 0x70字符串、0x66页面、成功/错误以及启动/休眠等返回需区分处理。普通执行反馈受bkcmd配置影响，当前官方文档写上电默认2，即仅报错；按钮/get等返回另有规则。
- printh发送指定的原始字节，不会自动给自定义数据加包头或结束符；第一版优先用已核对的标准按钮事件，避免混用无规则打印。

新增`src/rfsig/tjc_protocol.py`：短文本/非负int32值的有限命令编码，支持按钮、页面、数值、有限长度字符串及已列举状态返回；处理拆包/粘包，未知/损坏帧报错并清缓冲。它是协议子集，无串口IO，不是已验证的完整TJC驱动。

`tests/test_tjc_protocol.py`共17项通过，包含官方示例、分段/连续帧、数值0x00FFFFFF/0xFFFFFFFF、错误事件、超长输入及命令注入拒绝。中文字体、转义、其他回包和实际波特率待实际HMI/型号明确后增加。

后续控制层仍需绑定实际页面/控件ID、按键去抖、应用确认、超时、断线重连和停止处理。串口收到按钮事件不等于立即允许RF；板端还要验证状态、参数、重复请求和原发射guard。该控制层尚未实现，本轮协议测试不会发射。

## 4. 工程下载方式

官方上位机为USART HMI，下载入口已归档。需按实际完整型号建立工程并编译，保留可编辑HMI与可下载TFT两种产物。本轮没有安装编辑器或下载用户屏幕工程。

串口下载：使用符合实物电平/供电的下载工具，TX/RX交叉并共地；编辑器进行联机和TFT传输。工程运行波特率与下载传输波特率是不同设置，下载教程示例不能当作实屏当前波特率读回。

SD下载：按官方要求使用不超过32GB的FAT32卡，根目录仅放一个适配型号的TFT文件，屏幕断电插卡、上电等待完成、再断电拔卡后重新启动。不得拿现有板卡启动SD卡直接格式化；本轮未操作任何磁盘或存储卡。

## 5. 下一步执行顺序

1. 确认实物完整型号，读取对应规格书、硬件配置图与匹配出厂工程；保留出厂资源备份。
2. 核对供电/电平/针序，先用独立下载/调试工具验证屏幕和简单页面，不占用旧板电脑控制台。
3. 制作发送端HMI页面，明确控件ID，模拟器及实屏验证按钮回传和状态更新。
4. 继续P60 UART候选的时序/初始化及可回退启动包审核；完成旧板独立UART物理回环。
5. 把受guard保护的控制服务下沉到旧P201，接入屏幕，验证应用/开始/停止、失联及断电恢复。P59目前是电脑端双板入口，不能直接等同旧板自主服务。
