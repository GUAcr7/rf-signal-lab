# 双板接收电平核算（替代"不需要衰减器"的说法）

- 日期：2026-10-17。
- 状态：**核算，未连接。** 板上电源已断，本轮没有任何射频连接动作。
- 本文替代 `EXP-TX-002.md` 第 5 节与 `START-HERE.md`/`TX-SOURCE-STATUS.json` 中"不需要衰减器"的表述。

## 0. 先说结论

**"不需要衰减器"这个说法撤回。** 它把**损坏阈值**当成了可用性判据，而这两件事完全不同：

| 问题 | 答案 | 依据强度 |
|---|---|---|
| 会不会**损坏** AD9361？ | 大概率不会（算术余量 27 dB） | 算术成立，但用未标定的线缆损耗做保守假设 |
| 会不会**过载/饱和**导致测量无效？ | **很可能过载**，当前 RX 增益配置下 −24.5 dBm 明显偏高 | **未实测，属推断** |
| 能不能现在直连？ | **不能。** 先按第 4 节的降幅步骤做 | — |

## 1. 我犯了什么错

`docs/design/two-board-rf-link.md` 第 53 行（早先写入）明确要求：

> 确认旧板 TX SMA 在所用频率/数字幅度/增益下的峰值输出上限，包含 PA；确认新板 RX **推荐输入范围**。取得衰减器最小衰减、额定输入功率、频段、接口与线缆参数。**不要将 2.5 dBm 芯片绝对最大当推荐目标。**

我在 `EXP-TX-002.md` §5 里做的正是被这条禁止的事：用 **AD9361 绝对最大输入 +2.5 dBm** 减实测 TX 峰值，得出"余量 27.07 dB，不需要衰减器"。

**同一个项目里，后面的结论违反了前面的纪律，而且没有引用它。** 这是本轮审查发现的最实质的问题之一。

## 2. 两个数被混为一谈

| 量 | 含义 | 数值 | 能不能当余量基准 |
|---|---|---|---|
| **绝对最大额定值** | 超过可能**永久损坏** | AD9361 RF 输入 **+2.5 dBm peak** | ❌ 只用于"别烧坏"，不能用于"能不能用" |
| **推荐/线性工作范围** | 不饱和、可用的输入区间 | **本项目尚未确证**，依赖增益设置 | ✅ 这才是连接判据 |

**关键**：AD9361 的可用输入上限随**接收增益**变化。当前板上读到的是：

```
in_voltage0_gain_control_mode = slow_attack    (AGC 自动)
in_voltage0_hardwaregain      = 71.000000 dB   (当前增益读数)
```

在 71 dB 这样高的增益下，饱和电平远低于 +2.5 dBm 的损坏阈值。**把 −24.5 dBm 直接送进去，即使不损坏，也极可能让 ADC 削顶，测出来的 IQ 是失真的。**

**我没有做过饱和测试，所以不给具体饱和门限数字** —— 那需要实测（第 5 节）。

## 3. 电平余量（分两个口径，不要混用）

### 3.1 损坏口径（算术，成立但条件受限）

| 项目 | 值 | 来源 |
|---|---:|---|
| 旧板 TX 峰值（连接器处实测） | **−24.50 dBm** | `results/p13-pwr-512d-.../level-512-minus2450dBm.jpg` |
| 同一信号在另一组衰减下的复测 | −24.57 dBm | `results/p13-session2-peak-.../marker-on-main-peak.jpg` |
| AD9361 RF 输入绝对最大 | **+2.5 dBm peak** | 项目早先核实 |
| **损坏余量（不含线缆）** | **27.00 dB** | 2.5 − (−24.50) |

**这个余量只回答"会不会烧坏"，且建立在三个未验证的前提上**：

1. 线缆/接头损耗按 **0 dB** 计（等于不把损耗当余量 —— 保守，但不是实测）
2. 旧板 TX 峰值仅在**下面这组冻结配置**下成立
3. 分析仪的绝对幅度**未标定**（接头与线缆损耗未测），所以 −24.5 dBm 本身带未定系统误差

### 3.2 可用性口径（未确证）

- AD9361 的**推荐输入范围**：❌ 未取得
- 当前 71 dB 增益下的**饱和门限**：❌ 未实测
- **结论：无法在连接前给出可用性判据。**

### 3.3 TX 配置冻结（余量只对下列配置成立）

| 参数 | 冻结值 |
|---|---|
| 数字峰值分量 | **512 / 2047** |
| TX 数字衰减 | **−10 dB** |
| 载波（TX_LO + 数字偏移） | 2,450,960,000 Hz |
| 采样率 | 30,720,000 |
| 端口 | `A`（实测输出到 TX1） |

**改动任一项，第 3.1 节的 27 dB 立即失效，必须重算。**

## 4. 连接前必须做的降幅步骤（未执行，待上板）

原则：**先让接收端在远离饱和的状态下看到信号，再逐步逼近。** 不要一上来就满幅度直连。

1. **接收端先设手动增益、最低增益**
   ```sh
   echo manual > /sys/bus/iio/devices/iio:device1/in_voltage0_gain_control_mode
   echo 0 > /sys/bus/iio/devices/iio:device1/in_voltage0_hardwaregain
   ```
   （`slow_attack` AGC 会自己往高增益调，不利于观察饱和）

2. **发射端先降到 1/8 幅度**：数字峰值 512 → **64**，即 **−18.06 dB**，预期 TX 峰值约 **−42.6 dBm**（按 20·log10(64/512) = −18.06 dB 推算；**实际需实测确认**）

3. 记录无信号时的 RSSI 基线，然后发射，读 `in_voltage0_rssi` 与一段短 IQ

4. **只有确认未饱和**，才逐步提高幅度（64 → 128 → 256 → 512），每一步都检查 IQ 是否削顶

5. 若任一档出现削顶：保持该档以下，或插入衰减器

**第 2 步的波形尚未生成**，需要新增一个 64 档的波形文件（现有的是 512/256/128）。

## 5. 如何判定"饱和"（连接后要看的证据）

### 5.1 主判据：**步进增益**，不是绝对电平

线性未饱和时，输入**幅度加倍**（功率变为四倍），测得的 IQ 功率应增加 **+6.02 dB**。功率加倍则只有 +3.01 dB。逐档加倍幅度并记录增量：

| 观察到 | 判定 |
|---|---|
| 每次幅度加倍都得到 **6.02 ± 0.5 dB** | 这两档与线性关系一致；不代表更高档或其他配置安全 |
| 增量 **> 6.52 dB** | 异常增益，检查配置、信号及采集对应关系；不能判为线性 |
| 某次加倍只增加 **< 5.5 dB** | **开始压缩**，停在该档以下 |
| 加倍后几乎不增（< 1 dB） | 严重饱和 |

**方向必须记清**：压缩时"加倍"得到的增量**变小**。

> ### ⚠️ 勘误（2026-10-17 审查后修正）
>
> 本文原表最后一行写的是：
>
> > "与降幅后的对照：幅度减半后功率下降明显**大于** 6.02 dB（因为不再削顶）"
>
> **方向说反了。** 若较高等级已压缩，其测得功率**低于**真实值，于是"降一档"测到的**下降量会小于** 6.02 dB，而不是大于。按原文判据会把线性区误判成压缩、把压缩区误判成正常。
>
> 已改为上面的"逐档加倍看增量"判据 —— 它不依赖先验假设，且能定位压缩从哪一档开始。

### 5.2 辅助判据（互相 corroborate）

| 观察面 | 饱和的表现 |
|---|---|
| IQ 直方图 | 明显的**端点堆积**（大量样本贴同一极大/极小值） |
| 时域波形 | 削顶成平顶，不是平滑起伏 |
| 频谱 | 带外互调产物异常抬高 |
| 本底噪 | 增益提高时底噪同步抬高，但信号峰不再等比抬高 |

**只有做过本节这些检查，才能对"能不能直连"下结论。**
